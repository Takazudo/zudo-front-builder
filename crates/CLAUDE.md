# crates/ — Rust test governance (`#[ignore]` manifest)

The authoritative home of the Rust `#[ignore]` manifest, its taxonomy and maintenance rules, and the nextest `e2e-heavy-*` test-group registration notes. Read it before:

- adding, removing, or reclassifying ANY `#[ignore]` attribute under `crates/`;
- editing test wiring in `.github/workflows/exam.yml` or `.github/workflows/health.yml`;
- editing `.config/nextest.toml` test-groups.

The repo-wide testing strategy (levels/tiers, required behaviors, flaky pipeline, b4push) lives in root `CLAUDE.md`; the docs site has its own `docs/CLAUDE.md`.

## `#[ignore]` taxonomy (5 machine-greppable prefixes)

Every `#[ignore]`d Rust test carries a reason starting with one of 5 taxonomy prefixes — `grep -rn '#\[ignore = "' crates/` and spot-check the prefix:

- `env-gate: <binary> — <how to run>` — needs an external binary present (no issue URL needed).
- `heavy: run with --ignored — <why>` — deliberate heavy/local-only test (no issue URL needed).
- `flaky: <issue-url>` — quarantined flaky test (issue URL mandatory).
- `verification: <why>` — one-time "it was done" proof, not a regression guard (no issue URL needed).
- `pending-feature: <issue-url>` — blocked on an unimplemented product feature or unwritten test body (issue URL mandatory).

Parity between this file's `env-gate:`/`heavy:`-tagged rows and their scheduled home (an exam.yml filterset entry or a health.yml workspace-resolved `--run-ignored ignored-only` lane) is not a point-in-time manual audit — `scripts/check-exam-ignore-parity.sh` (issue #2072) recomputes the diff mechanically by parsing both workflows' actual scopes, with an offline fixture-based unit test at `tests/unit/check-exam-ignore-parity.sh`. Run it before trusting this file's coverage claims.

## Maintenance rules

- **Update the manifest table below whenever a `#[ignore]` is added, removed, or reclassified.** The table's totals sentence and the taxonomy split must be re-derived at the same time.
- **Re-measure rather than trusting stated totals:** `grep -rn '#\[ignore = "' crates/ | grep -v ':[0-9]*: *//' | wc -l`, and the same pipeline with `| grep -o '#\[ignore = "[a-z-]*:' | sort | uniq -c` for the per-tag split. The `grep -v` guards against a `//` comment quoting the attribute text — one such comment inflated a naive grep by 1 between #1983 and #1985.
- **Rows are keyed by path + test fn name — no line numbers.** The old `file:line` convention drifted constantly (audits found drift from 1 to several thousand lines) and was dropped in the 2026-07 restructure (#2150). Do not reintroduce line numbers into rows.
- **Flip protocol** (epic #2078, corrected form): a `pending-feature` RED test is written with its assertions already in desired post-fix form, and the fix lands UNDER them — assertions are never rewritten to suit a fix (root `CLAUDE.md` rule 8; a sanctioned downgrade must be documented in the PR body and an epic-issue comment). When the fix lands: a unit/self-skipping test gets the attribute DELETED outright; a genuinely env-gated binary gets the tag swapped to `env-gate:` AND any health.yml `--skip` naming that test deleted in the same commit. Re-measure both counters in lockstep — zero `pending-feature` tags in `crates/` must coincide with zero live `--skip` arguments in `.github/workflows/` run lines: `grep -rn -- '--skip' .github/workflows/ | grep -v '^\S*:[0-9]*: *#'` (currently 1 match — an explanatory comment, not a live argument).
- **Self-skip convention:** a real-e2e binary whose tests self-skip at runtime when an optional external tool is absent (an env-gate exit-log convention, e.g. pnpm/npm/wrangler probes) is NOT `#[ignore]`d and runs on T1 — CI provides those tools, so the self-skip is a local-dev convenience, not a CI blocker. The bundler is native Rolldown inside the zfb binary (#4635), so no test self-skips for a missing bundler. e2e-heavy-* test-group membership is orthogonal to `#[ignore]` status. Precedents: `dev_serve_e2e`, `wasm_ssr_dev_smoke_e2e`, `embedded_host_request_time_e2e`, `dev_content_reload_2063_e2e` (issue #2098's reasoned non-tag), `dev_supervision_e2e`.
- **Quarantine (`flaky:`) has a paper trail and an exit** — the full pipeline lives in root `CLAUDE.md`'s "Flaky tests". A quarantined test must still run somewhere allowed-to-fail (locally via `-- --ignored`; weekly via exam.yml's `quarantine-heavy` filterset), and its row here records that home.
- **exam.yml filtersets are exact-name-scoped.** Adding an `env-gate:`/`heavy:` row means adding its exact name to exam.yml's filterset (or placing it inside an existing health.yml `--run-ignored ignored-only` workspace lane) in the same change — `scripts/check-exam-ignore-parity.sh` fails otherwise.

## nextest `e2e-heavy-*` test-groups

nextest schedules test *binaries* concurrently by default, which would boot several real `zfb dev`/`zfb build`/`zfb preview` V8+bundler processes at once and starve CPU/memory until their boot-deadline watchdogs flake. `.config/nextest.toml` defines two groups with `max-threads = 1`, together assigning exactly **54** heavy binaries (expanded by #4011; count the `binary(=` entries in both filters rather than trusting any prose):

- **31 flock-adopting (`e2e-heavy-locked`)** — these hold #1339's OS advisory flock (`crates/zfb-test-utils/src/cross_binary_lock.rs`), which is their process-level mutual-exclusion guarantee. The max-threads=1 group is runner-level CPU/memory admission control and prevents nextest from co-scheduling two flock holders, so no test burns its per-test wall clock spinning behind another: `build_terminates`, `client_bundling_cross_pipeline`, `cold_rewrite_prewarm_e2e`, `collection_seed_3133_baseline`, `dev_bind_before_walk_e2e`, `dev_build_static_parity`, `dev_build_then_dev_default_layout_e2e`, `dev_content_aggregate_cold_boot_e2e`, `dev_content_reload_2063_e2e`, `dev_dep_invalidation_1284_e2e`, `dev_out_of_root_collection_e2e`, `dev_poll_backend_e2e`, `dev_public_large_tree_smoke_e2e`, `dev_serve_e2e`, `dev_serve_injected_routes_e2e`, `dev_sibling_watch_1678_e2e`, `dev_supervision_e2e`, `embedded_host_request_time_e2e`, `esbuild_free_combined_e2e`, `foreign_pragma_acceptance`, `mirror_css_scan_mdx_e2e`, `page_extension_full_matrix_e2e`, `plugin_watch_hook_confirm_2170_e2e`, `preview_cross_mode_e2e`, `scanner_boundary_acceptance`, `scratch_dir_concurrent_e2e`, `ssr_contract_dev_warning_e2e`, `ssr_reload_self_heal_e2e`, `wasm_ssr_dev_smoke_e2e`, `wind_clean_warm_identity_e2e`, `workerd_parity_e2e`.
- **23 unlocked (`e2e-heavy-unlocked`)** — no flock; this max-threads=1 group is their SOLE serialization guard: `build_cleans_outdir`, `build_package_routes`, `build_package_routes_consumer`, `build_reproducibility_e2e`, `build_warnings_json`, `client_router_autoinclude_build`, `content_snapshot_no_deferred`, `css_command`, `css_modules_components_build`, `end_to_end_basic_blog_build`, `framework_packages_no_pnpm`, `gfm_footnotes_tasklists_confirm_build`, `html_minify_build`, `page_extension_route_table_build`, `plugin_diagnostics_confirm_2375_e2e`, `preview_signal_supervision_e2e`, `render_artifact_confirm_build`, `render_artifact_determinism_build`, `sibling_css_module_command_layer_build`, `strict_broken_links_e2e`, `wasm_ssr_adapter_e2e`, `wind_real_build_confirm_build`, `zudo_react_build`.

Six integration sources are deliberately excluded from the binary heuristic: `check_command` (runs only `zfb check --skip-tsc`; no V8 or native bundling), `collections_outside_root_build_check_snapshot` (in-process check/snapshot/build materialisation with mocked subprocess output; no V8 or native bundling), `diagnostics_fixtures` (pure framed-diagnostic rendering fixtures; never starts the zfb CLI), `embedded_node_modules_cache` (self-spawned cache protocol/process-race harness; no zfb, V8, or native bundling), `process_guard_support` (tests the shared `tests/support/process_guard.rs` kill-tree guard by spawning only `sh`/`powershell.exe`; #4481), and `version_report` (only the cheap already-built `zfb --version`/`-V` paths). `version_stamp_from_env` is not excluded: it is covered by the unlocked lane's exact `test(=version_stamp_from_env)` predicate, alongside the shared `render_pipeline` and `v8_host_adapter` predicates. Both groups carry a long per-test `slow-timeout` (`terminate-after` = 600s) so legitimate dev-server watchdogs are never killed as "hung".

The unlocked override deliberately carries all **3 test-name predicate classes** for heavy tests inside shared test targets that `binary(=...)` cannot reach: `render_pipeline::tests::eval_deferred_paths_via_worker_embedded_v8_non_literal_paths` and `version_stamp_from_env` by exact name, plus `test(/^v8_host_adapter::tests::/)` — the one PREFIX regex (epic #2008 review). None holds the cross-binary flock, so the unlocked lane is the correct contention class. Every test in the V8 module boots a real isolate by construction (one asserts a 5s wall-clock `Drop`-join bound — serialized rather than loosened), so a future addition is covered instead of silently unserialized. Verify membership with `cargo nextest show-config test-groups` (and under `--profile ci`); the predicates hold on the T1 gate and on exam.yml's ignored-manifest runs.

The split permits one locked and one unlocked test to run concurrently while keeping each lane at `max-threads = 1`. `DEFAULT_TIMEOUT` remains 360s because the locked lane removes flock contention instead of increasing the wait budget.

**Registration rule:** a new test binary that spawns `zfb dev`/`zfb build`/`zfb preview` (or boots V8/the bundler in-process) joins the filter in `.config/nextest.toml`, that file's header comment, and this section's buckets — all in the same commit. Per-binary rationale lives in `.config/nextest.toml`'s header comment and each test file's own header comment; group membership is orthogonal to `#[ignore]` status (several members are un-ignored and run on T1).

### Doctests & nextest mechanics (facts the T1 gate relies on)

- **nextest does NOT run doctests.** `health.yml` keeps a separate `cargo test --workspace --doc` step. Report its results for the exact source, feature selection and toolchain; do not maintain a fixed workspace total here. Ordinary runnable examples execute; `no_run` examples compile but do not execute (for example the `bundle_job.rs` example in `zfb-islands`); `ignore` examples are skipped. A rustdoc “passed” summary can include compile-only examples, so it is not an executed-example count. Macro-generated items can also emit ignored examples, so source-fence counting alone is not a complete inventory. Keep these categories separate from nextest results. The [PR 4315 receipt](https://github.com/Takazudo/zudo-front-builder/pull/4315#issuecomment-6266482957) reports 3 passed and 7 ignored at `bda633b3589e201737b02cf2060f7b24d41a45a7`; it does not establish that all three examples executed.
- **Retries are RECORDED, not hidden.** The `ci` profile sets `retries = 1`; a pass-on-retry is reported as a terminal `FLAKY` line and in the JUnit report (`target/nextest/ci/junit.xml`, uploaded as the `nextest-junit-ci` artifact) — the mechanical enforcement of "pass-on-retry is a triage signal, not a success" (#1341 consumes the telemetry). Do not raise `retries` to paper over a flake. Local runs (b4push `B4PUSH_FULL=1`) use nextest's default profile (`retries = 0`) so a local flake fails loudly.
- **required-features lane:** `cargo nextest run -p zfb-md-extras --features test-utils` DOES pick up the `required-features = ["test-utils"]`-gated targets (verified in #1340).
- **Inventory parity is guaranteed by reconciliation, not assumed.** #1340 diffed `cargo test --workspace -- --list` against `cargo nextest list --workspace --run-ignored all`: identical apart from doctests, and no test target uses `harness = false`. If you add a custom-harness or benchmark test target, re-run that reconciliation — nextest silently skips binaries it cannot drive.
