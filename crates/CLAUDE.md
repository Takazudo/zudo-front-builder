# crates/ — Rust test governance (`#[ignore]` manifest)

The authoritative home of the Rust `#[ignore]` manifest, its taxonomy and maintenance rules, and the nextest `e2e-heavy` test-group registration notes. Read it before:

- adding, removing, or reclassifying ANY `#[ignore]` attribute under `crates/`;
- editing test wiring in `.github/workflows/exam.yml` or `.github/workflows/health.yml`;
- editing `.config/nextest.toml` test-groups.

The repo-wide testing strategy (levels/tiers, required behaviors, flaky pipeline, b4push) lives in root `CLAUDE.md`; the docs site has its own `docs/CLAUDE.md`.

## `#[ignore]` taxonomy (5 machine-greppable prefixes)

Every `#[ignore]`d Rust test carries a reason starting with one of 5 taxonomy prefixes — `grep -rn '#\[ignore = "' crates/` and spot-check the prefix:

- `env-gate: <binary> — <how to run>` — needs an external binary present (no issue URL needed).
- `heavy: run with --ignored — <why>` — deliberate heavy/local-only test (no issue URL needed).
- `flaky: <issue-url>` — quarantined flaky test (issue URL mandatory).
- `verification: <why>` — one-time "it was done" proof, not a regression guard (no issue URL needed).
- `pending-feature: <issue-url>` — blocked on an unimplemented product feature or unwritten test body (issue URL mandatory).

Parity between this file's `env-gate:`/`heavy:`-tagged rows and their scheduled home (an exam.yml filterset entry or a health.yml `-- --ignored` step scope) is not a point-in-time manual audit — `scripts/check-exam-ignore-parity.sh` (issue #2072) recomputes the diff mechanically by parsing both workflows' actual scopes, with an offline fixture-based unit test at `tests/unit/check-exam-ignore-parity.sh`. Run it before trusting this file's coverage claims.

## Maintenance rules

- **Update the manifest table below whenever a `#[ignore]` is added, removed, or reclassified.** The table's totals sentence and the taxonomy split must be re-derived at the same time.
- **Re-measure rather than trusting stated totals:** `grep -rn '#\[ignore = "' crates/ | grep -v ':[0-9]*: *//' | wc -l`, and the same pipeline with `| grep -o '#\[ignore = "[a-z-]*:' | sort | uniq -c` for the per-tag split. The `grep -v` guards against a `//` comment quoting the attribute text — one such comment inflated a naive grep by 1 between #1983 and #1985.
- **Rows are keyed by path + test fn name — no line numbers.** The old `file:line` convention drifted constantly (audits found drift from 1 to several thousand lines) and was dropped in the 2026-07 restructure (#2150). Do not reintroduce line numbers into rows.
- **Flip protocol** (epic #2078, corrected form): a `pending-feature` RED test is written with its assertions already in desired post-fix form, and the fix lands UNDER them — assertions are never rewritten to suit a fix (root `CLAUDE.md` rule 8; a sanctioned downgrade must be documented in the PR body and an epic-issue comment). When the fix lands: a unit/self-skipping test gets the attribute DELETED outright; a genuinely env-gated binary gets the tag swapped to `env-gate:` AND any health.yml `--skip` naming that test deleted in the same commit. Re-measure both counters in lockstep — zero `pending-feature` tags in `crates/` must coincide with zero live `--skip` arguments in `.github/workflows/` run lines: `grep -rn -- '--skip' .github/workflows/ | grep -v '^\S*:[0-9]*: *#'` (currently 1 match — an explanatory comment, not a live argument).
- **Self-skip convention:** a real-e2e binary whose tests self-skip at runtime via `locate_esbuild()` (or an equivalent env-gate exit-log convention) is NOT `#[ignore]`d and runs on T1 — health.yml always stages a pinned esbuild, so the self-skip is a local-dev convenience, not a CI blocker. e2e-heavy test-group membership is orthogonal to `#[ignore]` status. Precedents: `dev_serve_e2e`, `wasm_ssr_dev_smoke_e2e`, `embedded_host_request_time_e2e`, `dev_content_reload_2063_e2e` (issue #2098's reasoned non-tag), `dev_supervision_e2e`.
- **Quarantine (`flaky:`) has a paper trail and an exit** — the full pipeline lives in root `CLAUDE.md`'s "Flaky tests". A quarantined test must still run somewhere allowed-to-fail (locally via `-- --ignored`; weekly via exam.yml's `quarantine-heavy` filterset), and its row here records that home.
- **exam.yml filtersets are exact-name-scoped.** Adding an `env-gate:`/`heavy:` row means adding its exact name to exam.yml's filterset (or placing it inside an existing health.yml `-- --ignored` step scope) in the same change — `scripts/check-exam-ignore-parity.sh` fails otherwise.

## nextest `e2e-heavy` test-group

nextest schedules test *binaries* concurrently by default, which would boot several real `zfb dev`/`zfb build`/`zfb preview` V8+esbuild processes at once and starve CPU/memory until their boot-deadline watchdogs flake. `.config/nextest.toml` defines `[test-groups.e2e-heavy]` with `max-threads = 1` and an override assigning **35** heavy binaries (re-measured 2026-07; the figure has drifted stale before — count the `binary(=` entries in the filter rather than trusting any prose):

- **22 flock-adopting** — these also hold #1339's OS advisory flock (`crates/zfb-test-utils/src/cross_binary_lock.rs`), so the test-group is runner-level defense in depth on top of the flock's process-level guarantee: `build_terminates`, `client_bundling_cross_pipeline`, `cold_rewrite_prewarm_e2e`, `dev_bind_before_walk_e2e`, `dev_build_static_parity`, `dev_content_aggregate_cold_boot_e2e`, `dev_content_reload_2063_e2e`, `dev_dep_invalidation_1284_e2e`, `dev_out_of_root_collection_e2e`, `dev_public_large_tree_smoke_e2e`, `dev_serve_e2e`, `dev_serve_injected_routes_e2e`, `dev_sibling_watch_1678_e2e`, `dev_supervision_e2e`, `embedded_host_request_time_e2e`, `mirror_css_scan_mdx_e2e`, `page_extension_full_matrix_e2e`, `plugin_watch_hook_confirm_2170_e2e`, `preview_cross_mode_e2e`, `ssr_reload_self_heal_e2e`, `wasm_ssr_dev_smoke_e2e`, `workerd_parity_e2e`.
- **13 build-only** — no flock; the test-group is the SOLE serialization guard: `build_cleans_outdir`, `build_package_routes`, `build_package_routes_consumer`, `client_router_autoinclude_build`, `content_snapshot_no_deferred`, `css_modules_components_build`, `end_to_end_basic_blog_build`, `gfm_footnotes_tasklists_confirm_build`, `html_minify_build`, `page_extension_route_table_build`, `sibling_css_module_command_layer_build`, `strict_broken_links_e2e`, `wasm_ssr_adapter_e2e`.

`check_command` and `framework_packages_no_pnpm` are deliberately excluded: the former runs only `zfb check`; the latter calls `zfb_build::bundle` in-process, never spawning `zfb` or booting V8. The group carries a long per-test `slow-timeout` (`terminate-after` = 600s) so legitimate dev-server watchdogs are never killed as "hung".

The same override carries **3 test-name predicates** for heavy tests inside shared test targets that `binary(=...)` cannot reach: `render_pipeline::tests::eval_deferred_paths_via_worker_embedded_v8_non_literal_paths` and `version_stamp_from_env` by exact name, plus `test(/^v8_host_adapter::tests::/)` — the one PREFIX regex (epic #2008 review): every test in that module boots a real V8 isolate by construction (one asserts a 5s wall-clock `Drop`-join bound — serialized rather than loosened), so a future addition is covered instead of silently unserialized. Verify membership with `cargo nextest show-config test-groups -p zfb --lib` (15 matched tests at last measure, identical under `--profile ci`). The predicates hold on the T1 gate and on exam.yml's ignored-manifest runs.

**Registration rule:** a new test binary that spawns `zfb dev`/`zfb build`/`zfb preview` (or boots V8/esbuild in-process) joins the filter in `.config/nextest.toml`, that file's header comment, and this section's buckets — all in the same commit. Per-binary rationale lives in `.config/nextest.toml`'s header comment and each test file's own header comment; group membership is orthogonal to `#[ignore]` status (several members are un-ignored and run on T1).

### Doctests & nextest mechanics (facts the T1 gate relies on)

- **nextest does NOT run doctests.** health.yml keeps a separate `cargo test --workspace --doc` step. Current baseline (verify before changing; do not trust stale counts): **5 doctests execute + pass** — `zfb-css` (2) and `zfb-islands` (3) — plus **8** example blocks listed but ignored/`no_run` (`zfb-islands` 3, `zfb-server` 2, `zfb-test-utils` 1, `zfb-render` 2), i.e. **13 doctest entries across 5 crates**. Neither `zfb-render` entry is hand-written — every `deno_core::extension!` emits a `rust,ignore` usage example (#2015, #2017); a `cfg(test)`-only `extension!` adds none. The doc-test step must not regress below this baseline.
- **Retries are RECORDED, not hidden.** The `ci` profile sets `retries = 1`; a pass-on-retry is reported as a terminal `FLAKY` line and in the JUnit report (`target/nextest/ci/junit.xml`, uploaded as the `nextest-junit-ci` artifact) — the mechanical enforcement of "pass-on-retry is a triage signal, not a success" (#1341 consumes the telemetry). Do not raise `retries` to paper over a flake. Local runs (b4push `B4PUSH_FULL=1`) use nextest's default profile (`retries = 0`) so a local flake fails loudly.
- **required-features lane:** `cargo nextest run -p zfb-md-extras --features test-utils` DOES pick up the `required-features = ["test-utils"]`-gated targets (verified in #1340).
- **Inventory parity is guaranteed by reconciliation, not assumed.** #1340 diffed `cargo test --workspace -- --list` against `cargo nextest list --workspace --run-ignored all`: identical apart from doctests, and no test target uses `harness = false`. If you add a custom-harness or benchmark test target, re-run that reconciliation — nextest silently skips binaries it cannot drive.
