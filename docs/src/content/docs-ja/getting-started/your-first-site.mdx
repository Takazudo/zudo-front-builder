## 新しいプロジェクトをスキャフォールドする

```bash
pnpm create zfb@latest my-site
# または
npm create zfb@latest my-site
```

<Tip title="実行する前に出力を見る">

[create-zfb.takazudomodular.com](https://create-zfb.takazudomodular.com) では、
このコマンドが生成するものをそのまま公開しています。`basic-blog` テンプレートを
`main` への push ごとにビルドしてデプロイしたものです。サイトの内容は一切手書き
していません。すべてのプルリクエストを通すのと同じクリーンルーム実行によって CI
で生成されるため、これから手元に入るテンプレートとずれることがありません。

</Tip>

<Note title="pnpm 11 に関する注意">

pnpm 11 の `minimumReleaseAge` により、新しいリリースから約 48 時間以内は
`create-zfb` の一つ前のリリースがインストールされることがあります。
`create-zfb` が起動時に古いインストールについて警告する場合は、
`pnpm create zfb@latest --config.minimumReleaseAge=0` で再実行するか、
代わりに `npm create zfb@latest` を使ってください。

</Note>

これは `create-zfb` イニシャライザを実行します。内部では `zfb new` を呼び出し、同梱の `basic-blog` テンプレートを `my-site/` にコピーします。`PATH` 上に pnpm があれば、zfb はテンプレートのコピー直後に `pnpm install` を自動実行します。なければ、自分で実行するよう促す短いメッセージを表示します。

```bash
cd my-site
```

zfb CLI をすでにグローバルインストールしている場合（[Installation](./installation.mdx) を参照）、`zfb new` を直接呼び出しても同じ結果が得られます。

```bash
zfb new my-site --template basic-blog
```

`--template basic-blog` はデフォルトなので、省略できます。Node.js 依存を一切必要としないプロジェクト向けに `node-free` テンプレートも利用できます。`package.json` を同梱せず、`.tsx` に加えて `.md`/`.html` のページエントリを使います。このページの書き方については [Markdown and HTML Pages](../architecture/md-html-pages.mdx) を参照してください。

`basic-blog` がスキャフォールドするのは、`zfb.config.ts`（JSON ではありません）、3 つのシード記事を持つ `blog` コンテンツコレクション、4 つのルート、そして 1 つのクライアント島です。同梱の `README.md` がツリーの案内になっており、[プロジェクト構造](./project-structure.mdx) が同じ範囲をより詳しく扱います。

<Note title="インポート指定子について">

ベアの `zfb` 系指定子（`zfb`、`zfb/content`、`zfb/paginate`、`zfb/zudo-react` などの対応サブパス）は、SSR、島のスキャナー、クライアントバンドル、JSX pragma の判定、zudo-wind のクラス抽出で、それぞれ対応する `@takazudo/zfb` の公開エントリへ解決されます。パッケージを参照するエントリでは、どちらの書き方も同じパッケージを指します。このドキュメントでは短い `zfb` 形式を使います。設定ローダーは `zfb/config` を別扱いし、内部のランタイム専用スタブへエイリアスします。

このビルド時のエイリアスは TypeScript の設定には反映されません。`zfb check` の動作も変わらず、プロジェクトの設定で TypeScript を実行し、`compilerOptions.paths` を注入しません。TypeScript とエディタは `components/zfb-shim.d.ts` の ambient 宣言を使ってベア指定子を解決します。シム全体と既存のシムを拡張する方法は[ベアの `zfb` インポートの型付け](../api/define-config.mdx#typing-bare-zfb-imports)を参照してください。

</Note>

## 開発サーバーを起動する

```bash
pnpm zfb dev
# または
npx zfb dev
```

ホストとポートを示す「ready」バナーが表示されます（デフォルトは `http://localhost:3000`）。zfb は固定された一連のプロジェクトルートを監視します。`pages/`・`content/`・`components/`・`layouts/`・`styles/`・`data/`・`src/` と、2 つの設定ファイル（`zfb.config.json`、`zfb.config.ts`）です。これに加えて、設定でコレクションの `path` 値や絶対パスの `extraWatchPaths` エントリとして宣言された任意のパスも監視します。デフォルトの `public/` ディレクトリは監視されません。これらのファイルはディスクから直接配信されます。監視対象のファイルを保存すると、接続中のブラウザにライブリロードがブロードキャストされます。

ホストとポートは CLI から上書きできます。これらは常に `zfb.config.ts` より優先されます。

```bash
pnpm zfb dev --port 4000 --host 0.0.0.0
# または
npx zfb dev --port 4000 --host 0.0.0.0
```

## ビルドとプレビュー

サイトの静的ビルドを生成するには:

```bash
pnpm zfb build
pnpm zfb preview
# または
npx zfb build
npx zfb preview
```

`zfb build` は CLI の `--outdir` → config の `outDir` → 組み込みデフォルトの `dist/` という順で選んだディレクトリへ書き出し、ファイルシステムルーターでルートを列挙し、静的ルートごとに 1 つの HTML ファイルを書き出します。build コマンドはサーバーを起動しないため、`--port` フラグはありません。

`zfb preview` も同じ出力ディレクトリの優先順位を使い、選択されたディレクトリを HTTP で配信します。preview の `--port` フラグは設定の `port` より優先されます。どちらも設定されていない場合、preview は組み込みデフォルトの `4321` を使います。

3 つのコマンドはすべて `zfb.config.*` の `outDir` を尊重します。build と preview では、明示的な `--outdir` が常に設定値より優先されます。

## プロジェクトを型チェックする

```bash
pnpm typecheck
# または
npx zfb check
```

`zfb check` は 1 回の実行で 2 つのことを行います。TypeScript でプロジェクトを型チェックすることと、各コレクションエントリのフロントマターを、`zfb.config.ts` でそのコレクションに宣言された JSON Schema に対して検証することです。ビルド自体はフロントマターを検証しないため、`title` や `date` の欠けた記事はここで捕まります。[CLI リファレンス](../api/cli.mdx) を参照してください。

## 動作するサンプル

[zfb-example-blog](https://github.com/Takazudo/zfb-example-blog) は、読んでそのままデプロイできるスタンドアロンのサンプルサイトです（[ライブビルド](https://zfb-example-blog.takazudomodular.com/)）。同梱テンプレートのコピーではなく独立したリポジトリとして保守されているため、ファイル構成は `zfb new` がスキャフォールドするものとは異なります。手元のプロジェクトの写しではなく、作り込まれた実例として読んでください。この例の詳しい解説は [Blog](/ja/docs/recipes/blog) にあり、その他のサンプルは [サンプル](../guides/examples.mdx) にまとまっています。

## Node-free のサイトを作る

[スタンドアロン版をインストール](./installation.mdx#standalone-installation)し、`zfb` を `PATH` に追加してから実行します。

```sh
zfb new my-site --template node-free
cd my-site
zfb dev
```

`node-free` は `package.json` を持たず、`pnpm install` や `npm install` は不要です。`zfb.config.json`、Markdown / HTML / TSX のページ、明示的な Wind スタイルシートを使います。[Markdown と HTML ページ](../architecture/md-html-pages.mdx)でページの書き方を確認できます。

開発サーバーの既定の URL は `http://localhost:3000` です。ページやスタイルを編集するとライブリロードします。別のアドレスで起動する場合は `zfb dev --port 4000 --host 0.0.0.0` を使います。

## Node-free のビルドとプレビュー

開発サーバーを Ctrl+C で停止してから、同じプロジェクトで実行します。

```sh
zfb build
zfb preview
```

ビルドは既定で `dist/` に静的ファイルを生成します。プレビューの既定の URL は `http://localhost:4321` です。設定の `outDir` は両コマンドに適用され、CLI の `--outdir` が優先します。プレビューのポートは `zfb preview --port 4000` で変更できます。build には `--port` はありません。

## Node-free の検証

```sh
zfb check --skip-tsc
```

Node なしで TypeScript 以外のチェックを実行します。完全な TypeScript 型チェックには Node と `tsc` が必要です。Cloudflare アダプタを使うデプロイにも Node が必要です。[Node が依然として必要なケース](./installation.mdx#node-が依然として必要なケース)を参照してください。

## 最初のデザインを自分のものにする

同梱の両スターターは Everyday デザインから始まります。用途別の色、独立した
横方向と縦方向の余白、読みやすい文字組み、共通の角丸ルールを持つ、編集可能な
プロジェクトの選択です。zudo-wind エンジンの暗黙のデフォルトではありません。

- 色・余白・文字組み・読み幅・角丸の値は `styles/design-system.css` で変更します。
- 使い分けは `DESIGN-NOTES.md` を参照してください。ホームに表示する短いルールは
  `components/design-rules.ts` にあります。デザインを変えたら説明も更新してください。
- Basic blog では `zfb.config.ts` が `design-tokens.json` と既存の Markdown 用
  トークンをマージします。`styles/global.css` のダーク用の値はテーマ切り替えに
  連動します。既存記事 **How this site is styled** がそのつながりを説明します。
- Node-free でトークン名を変える場合は `zfb.config.json` と `design-tokens.json`
  を揃えてください。明示的な Wind スタイルシートはバイナリ内で生成され、Node・
  パッケージのインストール・クライアント島は不要です。

[デザインシステム Playground](../playground/design-system.mdx) でルールを試し、
編集可能なファイルを書き出せます。既存ページの値を保持しながら、カテゴリと名前ごとに
トークンをマージしてください。現在のイニシャライザが選ぶのはサイトテンプレートです。
デザインシードの選択機能やシード用の CLI フラグはまだありません。
