## はじめる前に

zfb 6 は、`zfb` 実行ファイルに組み込まれたネイティブの Rolldown バンドラーですべてをバンドルします。対象はページと SSR、islands、クライアントスクリプト、module worker、`zfb.config.ts`、TypeScript 系のプラグインです。zfb 5 でもページ、islands、クライアントスクリプトは既定で Rolldown を使っていましたが、設定ファイル、プラグイン、`ZFB_BUNDLER=esbuild` のフォールバックのために esbuild のバイナリを同梱していました。zfb 6 はそのバイナリと、それを選択・設定するすべてのオプションを削除します。互換モードはありません。

既定の設定で `zfb` CLI を実行しているプロジェクトの多くは、ソースを変更する必要はありません。スクリプトと CI に下記の環境変数が残っていないか確認してください。zfb の Rust クレートを組み込むホストは変更点が多くなります。[Rust の組み込みホスト](#rust-の組み込みホスト)を参照してください。

これは zfb が所有する範囲の話です。公開されている zfb のパッケージはどれも esbuild に依存していませんが、wrangler、Vitest、tsx などのサードパーティの開発ツールは依存グラフに esbuild を引き続きインストールします。こちらは影響を受けません。

## 環境変数

シェルのプロファイル、CI のワークフロー、`.env` ファイル、パッケージのスクリプトから `ZFB_BUNDLER` と `ZFB_ROLLDOWN_PROTOTYPE` を削除してください。どちらかを設定すると、`rolldown` を含むどの値でも、すべてのコマンドが実行前に失敗します。

```text
ZFB_BUNDLER=esbuild: the esbuild bundler backend and its ZFB_BUNDLER selector were removed; zfb always bundles natively. Unset ZFB_BUNDLER.
```

`ZFB_ESBUILD_BIN` も削除してください。zfb はもう読み取らないため、ビルド時にも実行時にも効果はありません。

Rolldown でのビルド失敗を回避するために `ZFB_BUNDLER=esbuild` や `ZFB_ROLLDOWN_PROTOTYPE=0` を設定していたサイトでは、そのフォールバックはもう使えません。ネイティブバンドラーが拒否する入力とその対処は[トラブルシューティング](./troubleshooting.mdx)を参照し、それ以外のビルド失敗はバンドラーの問題として報告してください。

## バージョン出力とキャッシュ

`zfb --version` は、5.x の `embedded esbuild: <version>` の代わりに `embedded bundler: rolldown-24bc2d0` を出力します。この 2 行目を解析しているスクリプトは更新してください。`zfb -V` の出力は変わりません。

module worker のキャッシュと islands のビルドトークンは、バンドラーの識別子をキーにするようになりました。アップグレード後の最初のビルドでこれらは作り直されます。手動でキャッシュを削除する必要はありません。5.x と 6.0.0 でビルドしたページは、異なる islands のビルドトークンを持ちます。

## 設定ファイルとプラグイン

`zfb.config.ts` と `.ts`/`.tsx`/`.mts`/`.cts` のプラグインエントリは、`zfb` 実行ファイルの子プロセスである監視付きのコンパイラーワーカーがコンパイルします。契約は変わりません。設定ファイルは引き続き Node の組み込みモジュールを import できず、プラグインは引き続き外部パッケージを残したまま Node 22 向けの ESM にコンパイルされます。CLI がワーカーを自分で起動するので、CLI の利用者は何も変更する必要がありません。

## Rust の組み込みホスト

ここに挙げる変更は、zfb の Rust クレートに依存するプログラムにだけ当てはまります。

- **コンパイラーワーカーのランチャー。** `.ts` の設定ファイルや TypeScript 系のプラグインをバンドルするライブラリには、明示的なランチャーが必要です。ライブラリが `current_exe()` から導出することはありません。`main` の最初で `zfb_server::run_compiler_worker_if_requested()` を呼び、`ServerBuilder::compiler_worker(WorkerLauncher::new(std::env::current_exe()?).arg(COMPILER_WORKER_ARG))` を渡してください。より低レベルのホストは `zfb_config_loader::LoadOptions::compiler_worker` を設定するか、プラグインホストにランチャーを渡します。ランチャーがないと、`.ts` の設定ファイルは不足しているランチャーを名指しするエラーで失敗します。`zfb.config.json` と JavaScript のプラグインにはランチャーは不要です。[ライブラリとして組み込む](./embed-as-library.mdx)を参照してください。
- **クレート名の変更。** `zfb-rolldown-prototype` は `zfb-bundler`（`zfb_bundler`）になりました。`zfb`、`zfb-build`、`zfb-islands` の依存から `rolldown-prototype` の Cargo フィーチャーを削除してください。
- **esbuild の argv の廃止。** `run_prepared(&Command)`、`Request::decode`、`decode_argv` は削除されました。型付きの `BundleRequest` を組み立てて `zfb_bundler::bundle` を呼ぶか、`generate` のあとに `publish` を呼んでください。
- **islands のバンドラー。** `EsbuildSubprocessBundler` と `EsbuildSubprocessConfig` は `IslandsBundler` と `IslandsBundlerConfig` になり、非推奨の別名はありません。`extra_args` と `with_extra_env` は、型付きの `externals`、`conditions`、`node_path` フィールドに置き換えてください。任意の esbuild 引数に代わるものはありません。`binary_path` と `with_binary_path` は削除してください。
- **削除された esbuild の項目。** `EmbeddedEsbuildGetter`、`resolve_esbuild_binary_with_handle`、`resolve_esbuild_binary_with_env`、`DEFAULT_ESBUILD_SLOT`、`BundlerInput::esbuild_binary`、`render_pipeline::embedded_binary`、`zfb-toolchain-pins` の esbuild ピン、`zfb-binfetch` クレート、`zfb-test-utils` の `locate_esbuild` はなくなりました。呼び出しを削除してください。バイナリを受け取るバンドル経路はもうありません。
- **ソースからのビルド。** `zfb` をソースからビルドしても esbuild をダウンロードしたり配置したりしなくなり、ビルド時の `ZFB_ESBUILD_BIN` による上書きもなくなりました。

## チェックリスト

1. 6.0.0 のパッケージとバイナリを揃えてインストールし、`zfb --version` で `embedded bundler` の行を確認します。
2. zfb を実行するすべての環境から `ZFB_BUNDLER`、`ZFB_ROLLDOWN_PROTOTYPE`、`ZFB_ESBUILD_BIN` を削除します。
3. `zfb build` を実行し、主要なページ、islands、クライアントスクリプトをブラウザーで確認します。
4. 組み込みホストでは、コンパイラーワーカーのランチャーを追加し、`zfb-rolldown-prototype` を `zfb-bundler` に置き換え、削除された esbuild の API を置き換えてから、ホストをビルドします。
