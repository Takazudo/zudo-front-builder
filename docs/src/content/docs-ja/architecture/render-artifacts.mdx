<Info title="このページの範囲">

`emitRenderArtifacts` によるビルド出力を説明します。出力内容、正確な JSON の構造、各フィールドの意味と保証しないこと、対象ルート、アーティファクトの有無を決める領域のルールを扱います。

</Info>

`zfb build` は、一部のルートについて、そのページの Markdown/MDX コンテンツ領域を配信される形で記録する JSON ファイルを任意で出力できます。含まれるのは、レンダリング済み HTML フラグメント、slug 付きの見出し、元ソースのダイジェストです。プレビュー用の画面や検索インデクサーなど、配信 HTML を再解析せずにページの描画内容を使いたい外部の処理は、`dist/` をスクレイピングする代わりに、この小さなバージョン付きファイルを読めます。

デフォルトでは無効です。有効化は設定リファレンスの [`emitRenderArtifacts`](../api/define-config.mdx) と、[CLI リファレンス](../api/cli.mdx)の `--emit-render-artifacts` / `--no-emit-render-artifacts` を参照してください。対象は `zfb build` のみで、`zfb dev` はレンダーアーティファクトを出力しません。

<Note title="フラグを有効にしても配信ページは変わらない">

コンテンツ領域は、そのページ自身のレンダリング済み HTML から、配信ページと同じアセット URL とリンクのベースパスの書き換え後に取り出されます。`emitRenderArtifacts` の有効・無効を切り替えても、zfb が各ページについて `dist/` に書く HTML は 1 バイトも変わりません。アーティファクトは追加の出力経路であり、別のレンダリング結果ではありません。

</Note>

## JSON の構造

条件を満たすルート（後述の[領域のルール](#領域のルール)を参照）には、次の構造のファイルが出力されます。

```json
{
  "contractVersion": 1,
  "route": "/blog/hello-world/",
  "fragmentHtml": "<h1 id=\"hello\">Hello, zfb</h1>…",
  "headings": [
    { "depth": 2, "text": "Basic usage", "slug": "basic-usage" }
  ],
  "sourceDigest": "sha256:9f86d081884c7d659a2feaa0c55ad015a3bf4f1b2b0b822cd15d6c15b0f00a08"
}
```

フィールドの順序は `contractVersion`、`route`、`fragmentHtml`、`headings`、`sourceDigest` に固定され、`headings` の各要素も `depth`、`text`、`slug` の順です。整形済み JSON として末尾に改行を付けて書き出され、入力が同一なら繰り返しビルドしてもバイト単位で一致します。[決定性とバージョン管理](#決定性とバージョン管理)を参照してください。

- **`contractVersion`** — 現在は整数 `1`。下記の構造にフィールドの追加、削除、改名、意味の変更があるたびに更新されます。利用側は構造が不変だと仮定せず、この値で処理を分けてください。
- **`route`** — ルートの URL パス（例: `/blog/hello-world/`）。zfb 内部の出力パスではありません。
- **`fragmentHtml`** — 配信されるコンテンツ領域の HTML。後述の [fragmentHtml](#fragmenthtml) を参照してください。
- **`headings`** — コンパイラーがその領域に割り当てた見出しの一覧。後述の [headings](#headings) を参照してください。
- **`sourceDigest`** — その領域を生成した Markdown/MDX ソースのダイジェスト。後述の [sourceDigest](#sourcedigest) を参照してください。

## fragmentHtml

`fragmentHtml` は、配信ページと同じアセット URL とリンクのベースパスの書き換えを行った**後**、HTML の minify **前**に取り出したコンテンツ領域の HTML です。そのため、[`minifyHtml`](../api/define-config.mdx) の有効・無効にかかわらず、フラグメント内のアセット URL とベースパス付きリンクは配信ページと一致します。

`minifyHtml` が無効なら、`fragmentHtml` は zfb が `dist/` に書くページの一部分とバイト単位で一致します。アーティファクトからコピーしたバイト列と、配信 HTML ファイルの同じ範囲からコピーしたバイト列を区別できません。`minifyHtml` が有効でも、取得は minifier の実行前なのでフラグメントは minify 前のマークアップを保持します。配信ページが minify されても、フラグメント自体は minify されません。

## headings

`headings` は、ページのコンパイル済みモジュールが `headings` としてエクスポートするものと同じ、コンパイラーが割り当てた一覧です。描画される `<hN id="…">` の属性と同じ slug アロケーターを使うため、通常の書き方では各見出しの `slug` は `fragmentHtml` 内の対応する要素の `id` と一致します。

<Caution title="コンポーネントの上書きで DOM と異なる場合がある">

[MDX コンポーネント](./mdx-components.mdx)で独自の `h2` などを渡して見出しの描画を上書きすると、描画された DOM がコンパイラーの割り当てと異なる場合があります。`headings` は常にコンパイラーの割り当てを表し、描画済みフラグメントを再走査した結果ではありません。そのため、特殊な見出しの上書きでは両者が一致しないことがあります。

</Caution>

## sourceDigest

`sourceDigest` は `"sha256:"` に小文字の 16 進数 64 桁を続けた値です。エントリのディスク上の生ソースを、**読み取ったバイト列のまま**計算対象にします。フロントマターを含み、BOM の除去や CRLF の正規化は行いません。

<Warning title="描画済みフラグメントの ETag ではない">

`sourceDigest` が識別するのは描画結果ではなく、*ソースファイル*です。別ファイル（部分テンプレートや共有スニペット）を取り込むページでは、その依存先の変更によって再ビルド時の `fragmentHtml` が変わっても、エントリ自身のソースバイト列が変わらなければ `sourceDigest` は同じままです。`fragmentHtml` のキャッシュキーとして使わないでください。古い内容の検出が必要なら、`fragmentHtml` 自体かアーティファクト全体を比較してください。

</Warning>

## 領域のルール

ページ内で、単一の Markdown/MDX エントリをレンダリングしたマークアップの範囲を**コンテンツ領域**と呼びます。ルートにアーティファクトが出力されるかどうかは、描画されたページにトップレベルの領域がいくつあるかで決まります。

| ページ内のトップレベル領域 | 結果 |
|---|---|
| ちょうど 1 つ | そのルートのアーティファクトを出力します。 |
| 0 | 出力しません。レイアウトや、独自の Markdown 本文を持たない一覧の外枠など、多くのページには Markdown 由来の領域がありません。 |
| 兄弟として 2 つ以上 | 出力せず、ルート名を含むビルド警告を 1 件出します。各記事の `Content` を埋め込む一覧ページなどが典型例です。 |
| 入れ子 | **外側**の領域をルートの領域とし、そのメタデータをアーティファクトに使います。内側の領域のセンチネルは、ほかの領域境界と同じく、ページと抽出フラグメントの両方から除去します。 |

## 対象となるルート

アーティファクトには、Markdown/MDX のコンテンツブリッジ（`entry.Content`。[コンテンツコレクション](./content-collections.mdx)を参照）か、直接の Markdown ページ用に zfb が生成する同等の外枠で描画された*コンテンツ領域*が必要です。具体的には次のとおりです。

- **`entry.Content` で描画するコンテンツコレクションのエントリ** — [コンテンツコレクション](./content-collections.mdx)の通常の `getCollection()` / `getEntry()` 経路 — は、描画するページにかかわらず対象になります。
- **直接の `pages/*.md` ファイル**（[Markdown と HTML のページ](./md-html-pages.mdx)を参照）は対象です。zfb はコンパイル済み本文を生成 HTML の外枠で囲み、そこに領域マーカーを出力します。
- **直接の `pages/*.mdx` ファイルは対象になりません。** `.md` と異なり、そのコンパイル済みモジュール自体がルートのページモジュールになります。計測用の生成外枠がないので、内容が単純でもコンテンツ領域やアーティファクトは生成されません。
- **HTML 以外のルート**（JSON、XML、フィードなど、`zfb build` が HTML ページとして出力しないもの）は対象外です。フラグメントを取り出す HTML ページがありません。
- **`.html` のパススルーページ**（そのまま配信する `pages/*.html` ソース）は対象外です。`minifyHtml` が対象外とするのと同じ理由で、zfb の描画パイプラインを通りません。

## アーティファクトのパス

ルートの HTML 出力パスの拡張子 `.html` を `.json` に置き換え、`<outDir>/__zfb/render/` の下へ移してファイルパスを決めます。

```
dist/blog/hello-world/index.html  →  dist/__zfb/render/blog/hello-world/index.json
```

## 予約済みの属性名前空間

抽出には、一致する `data-zfb-region-id` を持つ `<template>` のセンチネル対 `data-zfb-render-region="start"` / `data-zfb-render-region="end"` を使います。zfb は `emitRenderArtifacts` が有効なときだけ領域の前後にこれを出力し、その領域からアーティファクトを生成したかどうかにかかわらず、配信前に必ずページから除去します。

`data-zfb-render-region` / `data-zfb-region-id` の属性対は**予約済みの名前空間**です。HTML を書く際に、この正確な属性の組み合わせを `<template>` 要素に指定しないでください。zfb の抽出処理が内部のセンチネルとして扱おうとします。

## 決定性とバージョン管理

ソース入力が同一なら、ルートのレンダーアーティファクトは別々のビルドでもバイト単位で一致します。これはルートマニフェスト `<outDir>/__zfb/routes.json` と同じ保証です。ビルド間で差分を取る利用側には、元のコンテンツが実際に変わったときだけ差分が現れます。

利用側は構造に依存する前に `contractVersion` を確認してください。将来、上記のフィールドを変更するときは、バージョン `1` のまま黙って構造を変えず、この値を更新します。
