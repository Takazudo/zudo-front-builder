## 候補の 4 つの結果

候補には次の 4 種類の結果があります。

| 結果 | 動作 |
| --- | --- |
| 解決されたユーティリティ | 生成ルールを出力します。 |
| 認識されたが無効な候補 | 診断を報告します。厳格な発生元では処理が失敗し、確信度の低いソーステキストでは監査情報になります。 |
| 通常のクラスまたはマーカー | ユーティリティルールを出力しません。受け入れられた `group` や `peer` マーカーはメタデータを持ちますが、CSS はありません。 |
| 構文不正、未対応、または未知の明示的なユーティリティ入力 | 診断を出して処理を失敗させます。 |

クラス属性内の `site-header` のようにユーティリティの基部を持たない名前は、通常の CSS クラスのテキストとして残ります。カタログの基部で始まる名前は、接尾辞を調べる前に最長一致する基部で解決します。たとえば `text-link` は `text` ユーティリティとして扱われ、色またはフォントサイズの対応するトークンがなければ ZW006 になります。同様に、`bg-panel`、`border-soft`、`font-title` のような手書きの名前は、CSS 側で所有するなら予約が必要です。すべての未知の名前を通常のクラスとみなすのではなく、綴り間違いや未設定のユーティリティを見つけるための厳格な分類です。確信度の低い完全なリテラルでも、有効ならルールを生成できますが、無効でもビルドは失敗しません。明示的なセーフリストとマニフェストの項目は厳格に扱います。

## 診断コード

| コード | 意味と重大度 |
| --- | --- |
| ZW001 | 候補の構文。クラス、セーフリスト、厳格なマニフェストではエラー。ほかのリテラルでは監査専用情報です。 |
| ZW002 | 未知または未設定のバリアント。発生元に応じた重大度は ZW001 と同じです。 |
| ZW003 | 重複または正規順でないバリアント連鎖。重複のない並べ替え可能な連鎖には提案が付くことがあります。 |
| ZW004 | 意図的に未対応の言語機能です。 |
| ZW005 | 無効な値、修飾子、負の値です。 |
| ZW006 | トークン、余白単位、デフォルトの不足です。 |
| ZW007 | 無効な設定、トークンスキーマ、トークン値です。検証に失敗します。 |
| ZW008 | 未知の明示的ユーティリティ。セーフリストとマニフェストの項目は失敗しますが、通常のソースクラスはエラーになりません。 |
| ZW009 | スタイルシートに残るディレクティブまたは旧式の値関数。常にエラーです。 |
| ZW010 | 必須ソースまたはマニフェストの欠落、読み取り不能、無効。エラーです。 |
| ZW011 | 走査対象のソースが UTF-8 ではありません。警告を出してファイルをスキップし、以前の寄与を削除します。 |
| ZW012 | 動的な候補の組み立て。監査専用情報で、ユーティリティは推測されません。 |
| ZW013 | 1 つのクラスリストリテラル内のプロパティ競合。決定的な勝者を示す監査専用情報です。 |

診断レコードには、利用可能な候補、重大度、コード、発生元、メッセージ、任意の提案と拒否 ID が残ります。発生元は種類ごとに構造化されます。

| 発生元 | 位置データ |
| --- | --- |
| ソース | 安定したソース ID、UTF-8 バイトのオフセットと長さ、1 始まりの行とバイト列、囲むリテラル範囲、クラス位置かリテラル位置かの区別。 |
| セーフリスト | 所有者 ID と配列内の番号。 |
| マニフェスト | 生成者 ID、パス、候補の番号。 |
| 設定 | 設定キーのパス。 |
| role のクラス | role キー。 |
| スタイルシート | パスとソース範囲。 |

出現情報は保持され、発生元、オフセットまたはキー・番号、コード、候補のバイト列の順に並びます。

ZW001～ZW006 は、クラス、セーフリスト、厳格なマニフェストの発生元ではエラーです。確信度の低いソース位置では監査専用情報です。その位置で見つかった有効な完全候補は引き続き出力されます。基部名を持つクラスを手書きとして使う場合は、`authoredClasses: { "text-link": true }` のように完全な候補表記を `wind.authoredClasses` に追加します。この予約は候補全体に対するユーティリティの検証、診断、CSS 生成を抑止します。それ以外の場合は、ユーティリティの綴りを直すか不足トークンを宣言します。`site-header` のように一致するユーティリティ基部を持たない名前は通常のクラステキストとして残ります。

## explain と audit

`zfb wind explain` を実行すると、候補の解析と解決を調べられます。カタログ項目、言語のバージョンとリビジョン、トークンの結び付き、カテゴリ未検証の値、宣言、セレクタ、条件、完全なソートタプルが表示されます。`wind: false` のときは CSS を生成せず、無効という結果を返します。

`zfb wind audit` は、通常のクラス位置の名前、不足または使われていないユーティリティ、動的な断片、同じクラスリストリテラル内のプロパティ競合を調べます。マーカーと、完全一致する手書きクラスの許可リスト項目は除外します。競合の比較は 1 つのリテラル内に限られ、無関係な要素間では行いません。`wind: false` のときは生成が無効と報告し、候補レポートは空になります。

`--plan standalone`（既定）は、`--source` なしの `zfb css` と同じルート、つまり規約上のプロジェクトルートと、設定された `wind.sources` のパッケージルートと除外を監査します。`--plan build` は `zfb build` と `zfb dev` が走査するソースプランを監査します。プラグインの `setup` を実行して、パッケージ所有のルート、兄弟ミラールート、プラグインの仮想モジュールを見つけ、仮想モジュールは `plugin/<specifier>` として監査します。`preBuild` と `postBuild` フックは実行せず、ビルド出力も書き込みません。どちらのモードでも、最初に `wind audit plan: <mode>` と、走査するすべてのルート、仮想モジュール、マニフェスト、除外とその理由を出力します。

デフォルトでは、エラー重大度の指摘があっても監査完了時の終了ステータスは 0 です。その場合、標準エラーに `--fail-on error` の案内が表示されます。`--fail-on error` はエラー重大度の診断で失敗し、`--fail-on warning` は警告でも失敗します。`auditInfo` の指摘はどちらのしきい値にも影響しません。設定が無効な場合やソースの走査に失敗した場合は常に非ゼロで終了します。

`codeHighlight.roleClasses` は意図的に寛容です。有効なユーティリティは出力され、無効または未知の role 値はビルド診断を伴わない通常のクラスとして残ります。監査では無視された role として報告されることがあります。`authoredClasses` との完全一致は、すべての発生元でユーティリティの検証、生成、診断を抑止します。設定エラーやスタイルシートの検査は抑止できません。

## 残存ディレクティブと CSS コマンド

コンパイラは旧エンジンの import とディレクティブを拒否します。対象には `@tailwind`、任意の修飾子を伴う `@theme`、`@source`、`@custom-variant`、`@apply`、`@utility`、`@variant`、`@plugin`、`@config`、`@reference` が含まれます。`tailwindcss` とそのサブパスの import も拒否されます。宣言値内の旧式の関数 `theme()`、`--spacing()`、`--alpha()`、`--value()` もエラーです。診断には表記、スタイルシートのファイルと範囲が示され、[Tailwind からの移行](./coming-from-tailwind.mdx)へのリンクが付きます。

スキャナーはコメントと文字列の内容を無視し、エスケープされた CSS 識別子と import 文字列を復号します。禁止された import の解決を試みる前に、手書きのスタイルシートとすべての import 先を検査します。この検査は `wind` が `false` でも実行されます。通常の `@layer` と、レイヤーを明示する import は有効です。

単独の `zfb css` コマンドは引き続き wind コンパイラです。生成が有効なら、`--source` と `--no-auto-source` はソース発見、ハイライト用フラグはハイライトの意味を保ちます。`wind: false` のときは wind を生成せず、手書きの CSS とハイライトを処理します。別の `zfb wind explain` と `zfb wind audit` コマンドで候補の調査とソースの監査ができます。

## 生成物の識別子

生成されるリセット、トークン、登録、ユーティリティルールは、すべて仮想ソース `zudo-wind://spec/1` を使います。ソースレコードは言語バージョン 1、リビジョン 4 を示します。v1 は生成ソースマップを作らず、行番号の対応も保証しません。代わりに、候補からソースへの位置情報をルールのメタデータと診断に保持します。
