## 主な変更点

- zudo-wind はバージョン管理されたユーティリティ言語です。v1 は `spec: 1` で識別され、見慣れた表記でも別のエンジンとの互換性は保証しません。
- ユーティリティプラグインはありません。受け入れるカタログは言語バージョンごとに固定されます。
- 設定は `zfb.config.ts` または `zfb.config.json` のトップレベルの `wind` キーに置くデータです。CSS ディレクティブではエンジンを設定しません。
- パレット、余白単位、名前付きスケール、ブレークポイント、フォント、角丸、シャドウ、イージングは暗黙に供給されません。使うプロジェクトの値はすべて設定してください。
- ソースのスキャナーには完全なクラス候補が必要です。接頭辞と実行時の値を結合してもユーティリティにはなりません。
- 認識されないプロジェクトのクラスは通常のクラステキストとして残り、ユーティリティルールを生成しません。認識されたユーティリティでトークンが足りなければ、デフォルトを補う代わりに診断します。
- カタログ外の宣言とセレクタは、手書きの CSS または CSS Modules に置きます。

## ディレクティブ

wind の設定と候補の発見は CSS の外で行います。スタイルシートの移行時には Tailwind 専用のディレクティブを削除してください。入口または import 先のスタイルシートに残っていると、`wind: false` で生成を無効にしていても、zfb は表記とソース位置を示す ZW009 を報告し、処理に失敗します。

| Tailwind の構成要素 | zudo-wind での扱い |
| --- | --- |
| `@import "tailwindcss"` | 削除します。wind は独自のレイヤー前置きを用意し、選択したリセット、設定済みトークン、解決されたユーティリティを出力します。残った import は ZW009 です。 |
| `@import "tailwindcss/preflight"` | 削除し、`wind.reset` を明示的に選びます。リセットの選択肢は後述します。残った import は ZW009 です。 |
| `@import "tailwindcss/utilities"` | 削除します。ユーティリティは完全な候補と有限のカタログから生成されます。残った import は ZW009 です。 |
| `@tailwind base`、`@tailwind components`、`@tailwind utilities` | CSS を展開するディレクティブはありません。リセットを選び、コンポーネントルールは手書きの CSS に、カタログのユーティリティは完全な候補で記述します。残ったディレクティブは ZW009 です。 |
| `@theme` | 検証される値を `wind.tokens` に置きます。CSS 専用のプロパティは手書きの CSS の通常のカスタムプロパティとして残し、必要なユーティリティのトークンから参照します。 |
| `@source` | CSS では走査ルートを選べません。走査するファイルとパッケージルートは zfb のソースプランが管理します。[ソースと候補](./sources-and-candidates.mdx)を参照してください。 |
| `@source inline(...)` | アプリ所有の候補には所有者キー付きの `wind.safelist` 配列を使います。パッケージ所有の候補は、完全な v1 ユーティリティまたはマーカーに絞った、明示的なバージョン付き `wind.manifests` ファイルに入れます。各項目は厳格に検査され、無効または未知なら失敗します。パターン、波括弧展開、実行時補間の構文はありません。 |
| `@source not(...)` | CSS の否定ディレクティブはありません。ソースプランのルートと除外規則を使います。[ソースと候補](./sources-and-candidates.mdx)を参照してください。 |
| `@custom-variant` | 設定可能な組み込みバリアントは `dark` だけです。属性と値を `wind.dark` に設定し、ほかのセレクタ条件は手書きの CSS に記述します。 |
| `@apply` | ユーティリティ名を宣言に展開するディレクティブはありません。必要なセレクタに宣言を手書きします。 |
| `@utility` | カスタムユーティリティで言語を拡張することはできません。手書きの CSS にクラスを定義し、その完全なトークンをマークアップに書く場合は `wind.authoredClasses` で予約します。 |
| `@variant` | スタイルシート内でバリアントを展開するディレクティブはありません。対応する完全な候補をマークアップで使うか、セレクタと条件を手書きの CSS に記述します。 |
| `@plugin` | プラグインは読み込みません。組み込みカタログか手書きの CSS を使います。 |
| `@config` | 設定データはプロジェクトの `wind` キーに移します。CSS はユーティリティ設定ファイルを読み込みません。 |
| `@reference` | スタイルシートを展開するためのユーティリティ参照 import はありません。CSS Modules とグローバル CSS は手書きのままにし、値は `wind.tokens` に設定します。 |

スキャナーは旧式の宣言値関数 `theme()`、`--spacing()`、`--alpha()`、`--value()` も ZW009 で拒否します。コメントと文字列の内容は無視します。通常の `@layer` 宣言と、レイヤーを明示する CSS import は有効です。エラーの契約は[診断とツール](./diagnostics-and-tools.mdx)を参照してください。

## 設定

旧式のトップレベルの `tailwind` キーは zudo-wind では意味を持ちません。残っていれば、移行方法を示す設定エラーになります。`wind` に置き換えてください。切り替え後に `wind` キーを省略すると、空の v1 設定が有効になります。つまり生成は有効、リセットは `none`、トークンマップは空です。

~~~ts
import { defineConfig } from "zfb/config";

export default defineConfig({
  wind: {
    spec: 1,
    reset: "owned-v1",
    tokens: {
      spacingUnit: "0.25rem",
      colors: { panel: "var(--app-panel)" }
    },
    breakpoints: {
      sm: { minWidthPx: 640 }
    },
    dark: { attribute: "data-theme", value: "dark" }
  }
});
~~~

以前の無効化設定 `tailwind: { enabled: false }` は `wind: false` になります。これにより wind の生成、トークン検証、マニフェスト読み込み、候補走査を無効にします。手書きのグローバル CSS、CSS Modules、構文ハイライトは続き、残存ディレクティブの検査も続きます。フィールドとマージ規則は[設定](./configuration.mdx)を参照してください。

## テーマとトークン

v1 は色パレットや余白スケールを同梱しません。名前付きのサイズ、フォントファミリーやウェイト、文字サイズ、行の高さ、字間、角丸、シャドウ、z-index、イージング、ブレークポイントもありません。定数 `0`、`px`、カタログのキーワードはテーマを意味しません。

ユーティリティが必要とする値を `wind.tokens` に移します。`p-4` のような数値の余白は設定された `spacingUnit` を倍にし、名前付きの値は対応する群のマップから取得します。たとえば次の設定は、2 つの色ユーティリティをプロジェクト所有のプロパティに結び付けます。

~~~json
{
  "wind": {
    "tokens": {
      "spacingUnit": "0.25rem",
      "colors": {
        "panel": "var(--app-panel)"
      }
    }
  }
}
~~~

~~~css
:root {
  --app-panel: #f4f1ec;
}
~~~

これで `bg-panel` と `text-panel` は `colors.panel` から解決されます。トークンの項目は検証されるデータであり、実行可能な CSS や JavaScript ではありません。参照されるカスタムプロパティは手書きの CSS に残り、生成されたトークン変数がそれを指します。トークンや数値の余白単位がない場合、厳格な候補の発生元で報告され、デフォルトで補われません。マップと値の規則は[トークン](./tokens.mdx)を参照してください。

大文字の `DEFAULT` は無効です。小文字の `default` は、その意味が定義されたマップだけで使います。`radii.default` は `rounded`、`shadows.default` は `shadow` の値を与えます。色や余白のフォールバックにはなりません。

## リセット

デフォルトの `reset` は `none` で、リセット宣言は出力されません。ブラウザのデフォルトに対してページが置く前提に応じて選んでください。

| リセット | 主な動作 |
| --- | --- |
| `none` | リセットのバイト列はありません。手書きの CSS で変えない限り、リスト、見出しのサイズ、ボーダーの初期値、フォーム部品はブラウザ標準のスタイルを保ちます。 |
| `minimal-v1` | border-box に設定し、body の margin を削除し、フォーム部品にフォントを継承させます。リストマーカーの削除や見出しサイズの正規化はしません。 |
| `owned-v1` | border-box に設定し、margin、padding、ボーダーの初期幅を消去してボーダーを実線にします。リストマーカーを削除し、見出しにサイズとウェイトを継承させ、フォーム部品のフォントとボタン背景を正規化します。 |

`owned-v1` では、デザインに必要なリストマーカーを戻してください。スキャフォールドの `.prose` ルールは disc と decimal のリストを明示的に復元します。見出しはブラウザ標準のサイズを保持しないため、手書きの CSS または設定済みの文字サイズユーティリティで指定します。接尾辞のない border ユーティリティは、どのリセットでも自身で実線のボーダーを設定します。フォーム部品はフォントスタイルを継承し、リセットはブラウザ標準のフォーカスアウトラインと appearance を維持します。wind のユーティリティはレイヤーを持たず、手書きのグローバル CSS の後に続きます。名前付きレイヤーの通常の宣言より優先されますが、レイヤーのない手書きのルールは詳細度や後続順によって優先されます。リセットは明示的な zudo-wind の選択であり、別の preflight とバイト単位で一致する保証ではありません。宣言とレイヤー順は[カスケードとリセット](./cascade-and-reset.mdx)を参照してください。

### Tailwind preflight との違い

比較の基準は **Tailwind CSS 4.2.0 の preflight と `owned-v1`** です。先行するレシピ移行では Chromium 147・151 と WebKit 26.4 で測定しました。追加の #3451 フィクスチャは Chromium 151 と WebKit 26.5 で、375px と 1280px の幅を使って確認しました。いずれも網羅的なマトリクスではありません。測定したプロジェクトでは、Tailwind のテーマは `--default-font-family` を `--font-sans` から、`--default-mono-font-family` を `--font-mono` から解決します。

| セレクタ | Tailwind 4.2.0 preflight | `owned-v1` と影響 |
| --- | --- | --- |
| `html` のフォント | テーマの `--default-font-family` / `--font-sans` | 固定の `ui-sans-serif, system-ui, sans-serif`。子孫が継承するフォントが変わることがあります。 |
| `html` のタップ時の色 | `-webkit-tap-highlight-color: transparent` | ルールなし。ブラウザーのタップ時の色がすべての要素に継承されます。 |
| `code, kbd, samp, pre` のフォント | テーマの `--default-mono-font-family` / `--font-mono` | 固定の `ui-monospace, SFMono-Regular, Menlo, monospace`。両方が Menlo に解決される macOS ではスクリーンショットで差が見えないことがあります。 |
| `small` | `font-size: 80%` | ルールなし。ブラウザー標準のサイズになります。 |
| `sub, sup` | `font-size: 75%; line-height: 0; position: relative; vertical-align: baseline`、さらに `sub { bottom: -0.25em }` と `sup { top: -0.5em }` | ルールなし。行ボックスが広がり、レイアウトがずれることがあります。 |
| `hr` | `color: inherit` | 色のルールなし。ブラウザー標準色が境界線に影響することがあります。 |
| `button` と button/reset/submit 型の `input` | `appearance: button` | appearance のルールなし。ネイティブの表示が異なることがあります。 |
| `button, input, select, optgroup, textarea` | `border-radius: 0; background-color: transparent; opacity: 1` | `owned-v1` は button と button 型 input の背景を透明にしますが、Chromium で測定した text input はブラウザー標準の白い背景を保ちます。この宣言を揃えるには、下記の共通フォーム部品ルールを追加します。 |
| `::placeholder` | `opacity: 1` と、対応ブラウザーでは `color: color-mix(in oklab, currentcolor 50%, transparent)` | ルールなし。ブラウザー標準の色と不透明度になります（測定した Chromium では灰色）。 |
| `::file-selector-button` | 境界線と背景のない、文字のスタイルを継承する表示。右方向に 4px の余白があり、`appearance: button` | 疑似要素のルールなし。ネイティブの立体的なファイル選択ボタンが残ります。 |
| `[hidden]:where(:not([hidden="until-found"]))` | `display: none !important` | ブラウザー標準の hidden ルールのみ。`hidden` 属性の付いた要素が display ユーティリティで意図せず表示されることがあります。 |

元の **差分 0 要素** という結果は、そのフィクスチャの範囲内でした。元のフィクスチャには単独の text input がなく、`abbr[title]`、`progress`、`:-moz-focusring` も調べていません。#3451 のフィクスチャでは、下記の共通フォーム部品ルールを追加する前に、`owned-v1` の text input がブラウザー標準の白い背景を保ち、Tailwind では透明になる差が見つかりました。ルール追加後は Chromium 151 と WebKit 26.5 の両方で、両方の幅における全要素の標準 computed style と2つの疑似要素が一致しました。4組のスクリーンショットもピクセル単位で同一でした。Chromium ではリンクまで Tab キーで移動した後も、キーボードフォーカスリングが表示されました。この測定範囲はすべてのフォーム部品、フォント、プラットフォームを網羅するものではありません。要素ごとの `getComputedStyle` の差分には `::placeholder` と `::file-selector-button` は現れないため、疑似要素を明示して取得し、見た目が重要ならピクセルも比較してください。

測定された preflight の振る舞いを戻したい場合は、次の CSS を手書きのスタイルシートに追加します。プロジェクトのフォントが異なる場合、例のスタックを置き換えてください。v3 に暗黙のテーマはありません。したがって、この例のように `--font-sans` と `--font-mono` を手書き CSS で宣言するか、両方の `font-family` にリテラルのスタックを指定する必要があります。

~~~css
@layer base {
  :root {
    --font-sans: ui-sans-serif, system-ui, sans-serif, "Apple Color Emoji", "Segoe UI Emoji", "Segoe UI Symbol", "Noto Color Emoji";
    --font-mono: ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, "Liberation Mono", "Courier New", monospace;
  }
  html { font-family: var(--font-sans); -webkit-tap-highlight-color: transparent; }
  code, kbd, samp, pre { font-family: var(--font-mono); }
  small { font-size: 80%; }
  sub, sup { font-size: 75%; line-height: 0; position: relative; vertical-align: baseline; }
  sub { bottom: -0.25em; }
  sup { top: -0.5em; }
  hr { color: inherit; }
  button, input:where([type="button"], [type="reset"], [type="submit"]) { appearance: button; }
  button, input, select, optgroup, textarea {
    border-radius: 0;
    background-color: transparent;
    opacity: 1;
  }
  ::placeholder { opacity: 1; color: color-mix(in oklab, currentcolor 50%, transparent); }
  ::file-selector-button {
    box-sizing: border-box;
    margin: 0;
    margin-inline-end: 4px;
    padding: 0;
    border: 0 solid;
    border-radius: 0;
    background-color: transparent;
    font: inherit;
    font-feature-settings: inherit;
    font-variation-settings: inherit;
    letter-spacing: inherit;
    color: inherit;
    opacity: 1;
    appearance: button;
  }
  /* 任意指定。display ユーティリティがあっても hidden 要素を非表示に保つ。 */
  [hidden]:where(:not([hidden="until-found"])) { display: none !important; }
}
~~~

共通フォーム部品のルールでは、Tailwind が設定する border radius、背景色、不透明度を戻します。`button` のルールはファイル選択ボタンの疑似要素には適用されないため、独立したルールが必要です。Chromium 151 の画像ギャラリーのレシピでは、測定に基づくファイルボタンのルールを追加すると、テストした 2 ページの明暗両テーマでピクセルと疑似要素の差分が 0 になりました。`[hidden]` のルールは任意です。`!important` は Tailwind preflight と同様に display ユーティリティより優先させるためです。[レイヤーの前置き](./cascade-and-reset.mdx)では `zw-reset` が手書きの `base` より前にあるため、この補完ルールでリセットを上書きできます。キーボード操作時のフォーカス表示を残し、広範なリセットを無条件に貼り付けず、採用するルールを確認してください。リセット宣言を戻しても、ユーティリティの配置や関係セレクタの詳細度は戻りません。この差分は #3386 で追跡しています。

## バリアントと文法

次の表は各構成要素に対する v1 の扱いを示します。対応する連鎖はレスポンシブ、ダーク、関係、状態、疑似要素、ユーティリティの順で、カテゴリは重複できません。

| 構成要素 | 仕様上の扱いと規則 |
| --- | --- |
| `max-*` を含むブレークポイント | **変更して採用 (W02)。** 各名前に正の整数の `minWidthPx` を設定します。`sm` は最小幅、`max-sm` はその幅より下の排他的な範囲です。幅はピクセルで、ルートのフォントサイズには追従しません。 |
| `dark` | **変更して採用 (W09)。** 属性と値を設定するまで無効です。条件は要素自身または祖先に一致し、詳細度を増やしません。 |
| 状態バリアント | **採用 (W03)。** `hover`、`focus`、`focus-visible`、`active`、`disabled`、`focus-within`、`open`、`first`、`last` を使えます。すべての hover 条件には hover 対応のメディアクエリが付きます。 |
| `first` と `last` | **採用 (W03)。** それぞれ `:first-child` と `:last-child` を対象にします。 |
| 名前付き形式を含む `group-*` と `peer-*` | **変更して採用 (W04)。** 名前のない `group` と `peer` マーカーは対応する状態で使えます。group は祖先、peer は前の兄弟要素です。マーカーは単独で置き、CSS は出力しません。`group/menu` や `group-hover/menu:block` のような名前付き形式は拒否されます。 |
| 疑似要素バリアント | **採用 (W05)。** `before`、`after`、`marker`、`placeholder`、`backdrop` を使えます。`before` と `after` は `content` 宣言を追加しないため、必要なら手書きします。 |
| `aria-*` と `data-[...]` のバリアント | **診断で拒否 (W06)。** 属性バリアントは ZW004 です。セレクタは手書きの CSS に置きます。 |
| 任意セレクタのバリアント | **診断で拒否 (W07)。** `[&_a]:underline` のようなセレクタは ZW004 です。手書きの CSS に記述します。 |
| バリアントの連鎖 | **変更して採用 (W08)。** レスポンシブ、ダーク、関係、状態、疑似要素をそれぞれ最大 1 つ、指定順に使います。各機能とトークンが設定済みなら `sm:dark:hover:bg-panel` は正規形です。重複や順序違いは診断されます。 |
| 色の不透明度修飾子 | **採用 (W10)。** 色の接尾辞には 0～100 の整数を指定し、設定された色を透明色と oklab で混ぜます。`bg-panel/40` は有効です。余白やサイズには適用できません。 |
| 分数 | **変更して採用 (W11)。** 正の整数比を受け入れるのは、対象となるサイズと移動の基部だけです。`w-1/2` は利用可能なサイズ基準の半分を意味し、サイズのスラッシュは色の不透明度を意味しません。 |
| 任意の値 | **変更して採用 (W12)。** 対応するユーティリティの基部には、CSS プロパティの検証を通る、対応の取れた角括弧値を付けられます。空白にはアンダースコアを使い、エスケープしたものは文字どおり残ります。`url()` と、宣言などの構文を注入する値は拒否されます。 |
| 任意のプロパティ | **診断で拒否 (W13)。** `[overflow-wrap:anywhere]` のようなトークンは ZW004 です。宣言は手書きの CSS または CSS Module に置きます。 |
| `!important` の表記 | **診断で拒否 (W14)。** 先頭と末尾のどちらも ZW004 です。意図的な important 宣言は手書きの CSS に置きます。 |
| 負のユーティリティ | **採用 (W15)。** 負の値を許可するカタログ群だけが符号を受け入れ、群で定義された方法で値に適用します。`-mt-2` は有効、`-p-2` は無効です。 |
| `space-*` と `divide-*` | **変更して採用 (W20)。** `hidden` 属性で絞られた後続の表示対象の直接の子を対象にします。前者は対応する margin、後者は実線の左または上のボーダーを設定します。逆方向フラグはなく、疑似要素バリアントとも組み合わせられません。 |

候補の文法では区切りを分割する前に角括弧、丸括弧、引用符の対応を取るため、角括弧値内のコロンやスラッシュはバリアントや修飾子の区切りにはなりません。完全なカタログは[バリアント](./variants.mdx)、[ユーティリティの文法](./utility-grammar.mdx)、[ユーティリティリファレンス](./utilities/index.mdx)を参照してください。

## 以前は何も出力しなかったクラス

クラスに見える文字列のすべてがユーティリティルールを作るわけではありません。`site-header` のようなプロジェクトの名前は通常のクラスとしてマークアップに残り、wind はルールを出力しません。単独の `group` または `peer` マーカーもルールを出力せず、対応する候補のために関係メタデータを提供します。

| 候補の結果 | 動作 |
| --- | --- |
| 解決されたユーティリティ | wind がルールを出力します。 |
| 通常のクラスまたはマーカー | ユーティリティルールを出力しません。手書きの CSS ではスタイルを指定できます。 |
| 認識されたが無効なユーティリティ | 厳格なクラス、セーフリスト、マニフェストの発生元には診断が付きます。確信度の低いソーステキストでは監査情報です。不足トークンは自動補完されません。 |
| 構文不正、未対応、または未知の明示的なユーティリティ入力 | 診断を出して処理が失敗します。未知の通常のソースクラスは通常のクラステキストとして残ります。 |

`zfb wind audit` は、通常のクラス位置の名前、不足または使われていない候補、動的な断片、同じクラスリストリテラル内のプロパティ競合を列挙します。意図的な手書きクラスとスペルミスしたユーティリティの区別に役立ちますが、代替の候補は推測しません。CSS が全面的に所有するクラスは、完全一致する `wind.authoredClasses` 項目で検証と生成を抑止できます。[診断とツール](./diagnostics-and-tools.mdx)を参照してください。

## 移行例

basic-blog スキャフォールドの callout は `my-6`、`rounded-md`、`border-l-4`、`px-4`、`py-3`、`dark:bg-sky-950/40`、`group-hover:text-accent` などの実際の候補を使います。移行表では表記を維持します。採用されるとは、スキャフォールドがトークンとバリアントを明示的に設定した後に解決されるという意味です。

古いスタイルシートは Tailwind の import と独自のダークバリアントから始まり、`@theme` で 3 つのプロジェクト色を宣言します。

~~~css
@import "tailwindcss";
@custom-variant dark (&:where([data-theme="dark"], [data-theme="dark"] *));

@theme {
  --color-accent: oklch(0.53 0.21 258);
  --color-code-bg: #2b303b;
  --color-code-fg: #c0c5ce;
}
~~~

callout のソースには、次の tone 文字列があります。

~~~ts
tone: "border-sky-500 bg-sky-50 dark:bg-sky-950/40",
accent: "text-sky-700 dark:text-sky-300",
~~~

2 つの Tailwind ディレクティブを削除します。ユーティリティの値を設定に移し、CSS 専用のテーマプロパティは手書きのままにします。

~~~ts
import { defineConfig } from "zfb/config";

export default defineConfig({
  wind: {
    spec: 1,
    reset: "owned-v1",
    tokens: {
      spacingUnit: "0.25rem",
      colors: {
        accent: "var(--color-accent)",
        "sky-50": "#f0f9ff",
        "sky-300": "#7dd3fc",
        "sky-500": "#0ea5e9",
        "sky-700": "#0369a1",
        "sky-950": "#082f49"
      },
      radii: { md: "0.375rem" }
    },
    breakpoints: { sm: { minWidthPx: 640 } },
    dark: { attribute: "data-theme", value: "dark" },
    authoredClasses: { prose: true }
  }
});
~~~

この設定抜粋は、示した callout のトークンをカバーします。完全なスキャフォールド設定では、残りの候補と手書きの CSS が使うすべての色とスケールも宣言します。暗黙に補完されるマップはありません。

テーマプロパティを既存の手書きの base レイヤーに統合し、color-scheme と selection のルールを保ちます。

~~~css
@layer base {
  :root {
    --color-accent: oklch(0.53 0.21 258);
    --color-code-bg: #2b303b;
    --color-code-fg: #c0c5ce;
    color-scheme: light;
  }

  [data-theme="dark"] {
    --color-accent: oklch(0.79 0.13 254);
    color-scheme: dark;
  }
}
~~~

既存の base と components レイヤーは残します。wind の前置きが順序を定めます。手書きの `.prose` クラスはスタイルシートに残し、`authoredClasses` に完全な名前を登録します。手書きの CSS が以前 `var(--color-neutral-900)` を参照していた箇所は、出力されるトークン変数 `var(--zw-color-neutral-900)` に更新します。設定済みの `accent` トークンは手書きの `--color-accent` を参照するため、テーマ切り替えでは引き続きその値を変更できます。スキャフォールドは `owned-v1` リセットを使いますが、ほかのプロジェクトのデフォルトは `none` です。ここで扱うのは言語とスタイルシートの変更です。プロジェクト全体の移行順序は[v3 への移行](../guides/migrating-to-v3.mdx)を参照してください。

## 未対応の機能と代替方法

- 暗黙のパレットや余白スケールはありません。プロジェクトの値を `wind.tokens` に宣言します。
- ring、animation、scale、transform 文字列、任意プロパティのユーティリティはありません。手書きの CSS または CSS Module に宣言します。
- 属性や任意セレクタのバリアント、名前付き group や peer はありません。手書きのセレクタを使います。
- プラグイン定義のクラスや `@apply` 展開はありません。対応するユーティリティにはカタログの候補を使い、独自の宣言は CSS に残します。
- 実行時に組み立てる候補や正規表現のセーフリストはありません。有限のリテラルマップ、所有者キー付きセーフリスト、厳格なバージョン付きパッケージマニフェストを使います。

v1 カタログは[ユーティリティリファレンス](./utilities/index.mdx)、候補と移行エラーの調査は[診断とツール](./diagnostics-and-tools.mdx)を参照してください。
