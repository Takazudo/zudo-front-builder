Choose the pace of a transition: how it accelerates and slows between its starting and ending values.

## Quick reference

| Example class | Expected declarations |
| --- | --- |
| `ease-gentle` | `transition-timing-function: var(--zw-ease-gentle);` |

<Details title={"Example setup"}>

Every preview explicitly uses spec: 1, reset: "none", strict mode, spacingUnit: "0.25rem", no breakpoints, and defaultTransitionTimingFunction: "ease". The named example adds tokens.easings.gentle as cubic-bezier(0.2, 0, 0, 1); the other uses a direct CSS timing function. Both use a 300ms transition and move only 8px on hover or focus-visible. Authored demo CSS removes transition time for reduced-motion users.

</Details>

## Custom and named values

There are no built-in named easing tokens. Configure tokens.easings and refer to an entry with ease-&lt;name&gt;, as in ease-gentle. Arbitrary forms such as ease-[steps(3,end)] accept one CSS timing function. wind.defaultTransitionTimingFunction takes a CSS keyword or function, not a token name; an explicit ease-* utility overrides it in the same variant bucket.

**Related guides:** [Utility grammar](../utility-grammar.mdx) · [Variants](../variants.mdx)
