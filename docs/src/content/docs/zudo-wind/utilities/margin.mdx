Use margin to add space outside an element’s border. It changes the space around the element in normal layout; padding adds room inside its border, while gap belongs to the parent layout container.

## Quick reference

| Example class | Expected declarations |
| --- | --- |
| `m-4` | `margin-top: 1rem; margin-right: 1rem; margin-bottom: 1rem; margin-left: 1rem;` |
| `mx-8` | `margin-left: 2rem; margin-right: 2rem;` |
| `my-2` | `margin-top: 0.5rem; margin-bottom: 0.5rem;` |
| `mt-2` | `margin-top: 0.5rem;` |
| `mr-4` | `margin-right: 1rem;` |
| `mb-6` | `margin-bottom: 1.5rem;` |
| `ml-8` | `margin-left: 2rem;` |

<Details title={"Example setup"}>

The examples explicitly use spacingUnit: "0.25rem", reset: "none", strict mode and no breakpoints. Numeric suffixes multiply that unit, so m-4 emits 1rem on each physical side. No Tailwind scale or theme is inherited. wind-demo classes provide only the visible frames and cards; their CSS is shown with each preview.

</Details>

## Custom and named values

m-0 removes margin and m-px uses 1px without a spacing token. Other numeric suffixes need tokens.spacingUnit. Named values such as m-section need tokens.spacing; arbitrary values such as mt-[18px] do not. Margin roots use physical sides: mx means left and right, my means top and bottom, and mt/mr/mb/ml name one edge. They do not follow writing direction. Margin accepts negative values by putting a dash before the root, such as -mt-3; padding and gap do not. It also accepts auto: mx-auto centers a fixed-width block when horizontal space is available, while vertical auto margins need a layout context that distributes free space.

**Related guides:** [Utility grammar](../utility-grammar.mdx) · [Variants](../variants.mdx)
