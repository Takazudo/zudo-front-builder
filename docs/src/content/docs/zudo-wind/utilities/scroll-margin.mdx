Use scroll-margin to add an outset around a target when the browser scrolls it into view, including fragment navigation and scroll snapping. It does not create visible layout space around the element.

## Quick reference

| Example class | Expected declarations |
| --- | --- |
| `scroll-m-6` | `scroll-margin-top: 1.5rem; scroll-margin-right: 1.5rem; scroll-margin-bottom: 1.5rem; scroll-margin-left: 1.5rem;` |
| `scroll-mx-8` | `scroll-margin-left: 2rem; scroll-margin-right: 2rem;` |
| `scroll-my-2` | `scroll-margin-top: 0.5rem; scroll-margin-bottom: 0.5rem;` |
| `scroll-mb-4` | `scroll-margin-bottom: 1rem;` |
| `scroll-ml-6` | `scroll-margin-left: 1.5rem;` |
| `scroll-mr-6` | `scroll-margin-right: 1.5rem;` |
| `scroll-mt-8` | `scroll-margin-top: 2rem;` |

<Details title={"Example setup"}>

The examples explicitly use spacingUnit: "0.25rem", reset: "none", strict mode and no breakpoints. Each preview contains a real link and target inside its own scrollable frame. Its native base element points to about:srcdoc so a fragment such as #top-target resolves within the preview document. Numeric suffixes multiply spacingUnit; no Tailwind scale or theme is inherited. wind-demo classes draw only the scroll frames and targets.

</Details>

## Custom and named values

scroll-m-0 removes the outset and scroll-m-px uses 1px without a spacing token. Other numeric suffixes need tokens.spacingUnit; named values such as scroll-mt-sticky need tokens.spacing; arbitrary lengths such as scroll-mt-[72px] need no spacing token. Negative values are supported with a dash before the root, as in -scroll-mt-4. The x and y roots use physical sides: scroll-mx means left and right, scroll-my means top and bottom. The side roots are also physical, not logical start/end directions. Set scroll-margin on the target whose position matters; use scroll-padding on the scroll container when you need an inset for all of its targets.
