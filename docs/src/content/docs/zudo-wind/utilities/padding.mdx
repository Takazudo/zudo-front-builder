Use padding to create room between an element’s content and its border. Choose all sides, a physical axis, or a single edge.

## Quick reference

| Example class | Expected declarations |
| --- | --- |
| `p-4` | `padding-top: 1rem; padding-right: 1rem; padding-bottom: 1rem; padding-left: 1rem;` |
| `px-8` | `padding-left: 2rem; padding-right: 2rem;` |
| `py-2` | `padding-top: 0.5rem; padding-bottom: 0.5rem;` |
| `pt-2` | `padding-top: 0.5rem;` |
| `pr-4` | `padding-right: 1rem;` |
| `pb-6` | `padding-bottom: 1.5rem;` |
| `pl-8` | `padding-left: 2rem;` |

<Details title={"Example setup"}>

These examples explicitly use spacingUnit: "0.25rem", reset: "none", strict mode and no breakpoints. p-4 emits 1rem on each side; px-8 emits 2rem on the left and right. No Tailwind spacing scale or theme is inherited. The colored area and dashed content guide use authored wind-demo scaffold CSS, shown with each preview.

</Details>

## Custom and named values

p-0 removes padding and p-px uses 1px without a spacing token. Other numeric suffixes need tokens.spacingUnit. Named values such as p-card need tokens.spacing; arbitrary values such as p-[18px] do not need that scale. The same value forms work for each axis and edge. Padding uses physical sides, not logical start/end directions, and never accepts negative values or auto. Use underscore encoding for spaces in arbitrary calc values.

**Related guides:** [Utility grammar](../utility-grammar.mdx) · [Variants](../variants.mdx)
