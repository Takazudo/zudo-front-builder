## The wind key

The root configuration accepts `wind` in both `zfb.config.ts` and `zfb.config.json`. After the cutover, an absent key has the same behavior as an empty object: generation is enabled with reset `none`, empty token maps, and sources supplied by zfb's source planner.

```ts
import { defineConfig } from "zfb/config";

export default defineConfig({
  wind: {
    spec: 1,
    reset: "none",
    defaultTransitionTimingFunction: "cubic-bezier(0.4, 0, 0.2, 1)",
    tokens: {
      spacingUnit: "0.25rem",
      colors: { panel: "var(--app-panel)" }
    },
    breakpoints: {
      sm: { minWidthPx: 640 }
    },
    dark: { attribute: "data-theme", value: "dark" },
    safelist: {
      app: ["sm:hover:bg-panel"]
    },
    authoredClasses: {
      prose: true
    },
    manifests: {
      widgets: { path: "@example/widgets/wind.json" }
    }
  }
});
```

### Manifest path resolution

Manifest paths are resolved from a base directory. A bare package specifier such as `@example/widgets/wind.json` uses Node resolution and the producer package's `exports`; this is the recommended spelling and works with pnpm's package layout. Export the manifest from the producer package:

```json
{
  "name": "@example/widgets",
  "exports": {
    "./wind.json": "./wind.json"
  }
}
```

Paths beginning with `./` or `../` resolve from the project root, meaning the directory that contains `zfb.config.ts` or `zfb.config.json`, regardless of the current working directory. When a manifest declaration comes from a preset built with `definePreset()`, zfb records the preset package as its source, so both relative paths and bare package specifiers resolve from that preset package's directory instead.

### Source exclusions and package roots

`sources` adjusts the source plan. Both lists are optional and default to empty, so an unset `sources` keeps the default plan.

```ts
wind: {
  sources: {
    exclude: ["src/**/__tests__/**", "worker"],
    packageRoots: ["@example/widgets", "./packages/ui"]
  }
}
```

Each `exclude` entry is a glob matched against paths relative to its declaring root: the project root, or the preset package for a declaration from `definePreset()`. A pattern excludes a path when it matches the path or one of its parent directories, so `worker` or `worker/` excludes everything under `worker/`. `*` does not cross `/`; use `**` for any depth. Exclusions apply to every source root, win over explicit `--source` files, and only remove files under their own declaring root. Negated (`!`), absolute, and `..` patterns are rejected. Test files are not excluded unless a pattern names them.

Each `packageRoots` entry is either a `./` or `../` path from the declaring root, or an installed package name with an optional subpath such as `@example/widgets/dist`, found through the `node_modules` directories above the declaring root. A package root must be an existing directory that is neither the project root nor one of its ancestors, and it is scanned with its own `dist` and `node_modules`, ignoring gitignore rules. Output, `--output`, and scratch directories stay excluded inside it.

The same object is valid as the value of the `wind` property in JSON:

```json
{
  "wind": {
    "spec": 1,
    "reset": "none",
    "tokens": {
      "spacingUnit": "0.25rem",
      "colors": {
        "panel": "var(--app-panel)"
      }
    },
    "breakpoints": {
      "sm": {
        "minWidthPx": 640
      }
    }
  }
}
```

`wind: false` turns off wind generation, token validation, manifest loading, and candidate scanning in build, dev, and the standalone CSS command. Authored global CSS, CSS Modules, and highlight processing still run. Checks for leftover directives in stylesheets still run even when wind is false. A non-none reset can emit CSS without utility candidates; an empty enabled configuration with no resolved rules emits no wind stylesheet.

## Fields

| Field | Meaning |
| --- | --- |
| `spec` | Optional language version. The only accepted value is `1`; the default is `1`. |
| `reset` | One of `none`, `minimal-v1`, or `owned-v1`. The default is `none`. |
| `defaultTransitionTimingFunction` | One CSS timing function or keyword used by transition utilities. It defaults to `ease`; an explicit `ease-*` utility takes precedence in the same variant bucket. |
| `tokens` | Project supplied values. All maps default to empty; see [Tokens](./tokens.mdx) for names, value validation, and emitted variables. |
| `breakpoints` | Names mapped to objects containing a positive integer `minWidthPx`. Equal widths are a configuration error. |
| `dark` | Either `false` (the default) or an object with required `attribute` and `value` strings. |
| `safelist` | Owner IDs mapped to arrays of complete candidates. Each owner supplies its full set. |
| `authoredClasses` | Complete candidate spellings mapped to `true`; exact matches stay authored and suppress utility validation, diagnostics, and generated CSS. Include variants when reserving a variant-bearing candidate. |
| `manifests` | Producer IDs mapped to a nonempty `path` for a candidate manifest. |
| `sources` | Optional `exclude` globs and `packageRoots` paths, each resolved from its declaring project or preset package. |

The dark attribute must be a lowercase HTML attribute identifier. Its value must be nonempty and contain no control characters. Owner and producer IDs use nonempty ASCII letters, digits, dots, underscores, slashes, or hyphens, and start with a letter or digit. Authored class keys must be complete, nonempty tokens without whitespace or control characters.

`defaultTransitionTimingFunction` takes a CSS timing function value, not a name from `tokens.easings`. Configure `tokens.easings` for explicit `ease-*` utilities; those utilities sort after transition defaults and override them in the same variant bucket. The configured value is validated as one timing function or keyword. `transition-none` emits no default duration or timing function.

## Strict validation and merging

Every nested config object has a closed set of field names. Unknown fields, nulls, wrong value types, unsupported versions or reset names, duplicate breakpoint widths, and invalid token data fail validation. A partial object is allowed because omitted optional objects receive their documented empty defaults.

When preset and user configuration are merged, objects merge recursively with user values taking precedence. Distinct safelist owners and manifest producers remain distinct. Every `sources` declaration is kept with its own declaring root: preset entries come first in preset order, followed by the user's, and a user declaration does not replace a preset's. For the same safelist owner, the user's array replaces the preset array; arrays are not concatenated. Authored class maps merge by key with user values taking precedence. There is no per-entry deletion marker in v1, and setting `wind` to false disables the whole system.

A leftover top-level `tailwind` key is a hard error with a named migration message. Follow [the v3 migration guide](../guides/migrating-to-v3.mdx) to update it.
