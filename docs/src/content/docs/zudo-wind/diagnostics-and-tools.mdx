## Four candidate outcomes

A candidate has one of four results:

| Outcome | Result |
| --- | --- |
| Resolved utility | Emit its generated rule. |
| Recognized but invalid candidate | Report a diagnostic. Strict origins fail the pass; lower-confidence source text is audit information. |
| Ordinary class or marker | Emit no utility rule. An accepted `group` or `peer` marker carries metadata but has no CSS. |
| Malformed, unsupported, or unknown explicit utility input | Fail the pass with a diagnostic. |

An unrelated name such as `site-header` in a class attribute remains ordinary CSS-class text because it has no utility root. When a name starts with a catalog root, resolution chooses the longest matching root before checking its suffix. For example, `text-link` is checked as a `text` utility and receives ZW006 when neither a matching color nor font-size token is configured; similarly, authored names such as `bg-panel`, `border-soft`, or `font-title` need to be reserved if CSS owns them. This strict classification keeps misspelled or unconfigured utilities visible instead of guessing that every unknown name is an ordinary class. Low-confidence complete literals can contribute valid rules, but invalid ones do not fail a build. Explicit safelist and manifest entries are strict.

## Diagnostic codes

| Code | Meaning and severity |
| --- | --- |
| ZW001 | Candidate syntax. Error for class, safelist, or strict manifest origins; audit-only information for other literals. |
| ZW002 | Unknown or unconfigured variant. Uses the same origin-aware severity as ZW001. |
| ZW003 | Duplicate or noncanonical variant chain. A sortable unique chain may include a suggestion. |
| ZW004 | Deliberately unsupported language feature. |
| ZW005 | Invalid value, modifier, or negative. |
| ZW006 | Missing token, spacing unit, or default. |
| ZW007 | Invalid config, token schema, or token value; validation fails. |
| ZW008 | Unknown explicit utility; safelist and manifest entries fail, while ordinary source classes are not errors. |
| ZW009 | Leftover stylesheet directive or legacy value function; always an error. |
| ZW010 | Required source or manifest is missing, unreadable, or invalid; error. |
| ZW011 | Scanned source is not UTF-8; warning, skip the file, and remove its old contribution. |
| ZW012 | Dynamic candidate construction; audit-only information, no utility is invented. |
| ZW013 | Property conflict inside one class-list literal; audit-only information explains the deterministic winner. |

Diagnostic records retain the candidate where available, severity, code, origin, message, optional suggestion, and optional rejection ID. Origins are structured by kind:

| Origin | Location data |
| --- | --- |
| Source | Stable source ID, UTF-8 byte offset and length, one-based line and byte-column, enclosing literal span, and whether the position is a class or literal. |
| Safelist | Owner ID and array index. |
| Manifest | Producer ID, path, and candidate index. |
| Config | Configuration key path. |
| Role class | Role key. |
| Stylesheet | Path and source span. |

Occurrences are retained and ordered by origin, offset or key/index, code, and candidate bytes.

ZW001 through ZW006 are errors at class, safelist, and strict manifest origins. At lower-confidence source positions they are audit-only information; a valid complete candidate found there still emits. If a utility-root name is intended as an authored class, add its exact complete spelling to `wind.authoredClasses`, for example `authoredClasses: { "text-link": true }`. This reservation suppresses utility validation, candidate diagnostics, and generated CSS for that full candidate. Otherwise, correct the utility spelling or declare the missing token. A name with no matching utility root, such as `site-header`, remains ordinary class text.

## Explain and audit

Run `zfb wind explain` to inspect how a candidate is parsed and resolved. Explain exposes the catalog entry, language version and revision, token bindings, any category-unverified value, declarations, selector, conditions, and complete sort tuple. With `wind: false`, it returns a disabled outcome without generating CSS.

Run `zfb wind audit` to inspect ordinary class-position names, missing or dead utilities, dynamic fragments, and property conflicts within an enclosing class-list literal. It excludes markers and exact authored-class allowlist entries. Conflicts are compared within one literal, not between unrelated elements. With `wind: false`, audit reports generation disabled and an empty candidate report.

`--plan standalone` (the default) audits the same roots as `zfb css` without `--source`: the conventional project roots plus configured `wind.sources` package roots and exclusions. `--plan build` audits the plan `zfb build` and `zfb dev` scan. It runs plugin `setup` to discover package-owned routes, sibling mirror roots, and plugin virtual modules, which are audited as `plugin/<specifier>`. It runs no `preBuild` or `postBuild` hook and writes no build output. Either mode first prints `wind audit plan: <mode>` followed by every scanned root, virtual module, manifest, and exclusion with its reason.

By default, a completed audit exits with status 0 even when it reports error-severity findings; stderr then recommends `--fail-on error`. `--fail-on error` fails on error-severity diagnostics, while `--fail-on warning` also fails on warnings. `auditInfo` findings do not affect either threshold. Invalid configuration and source scan failures always exit nonzero.

`codeHighlight.roleClasses` is deliberately tolerant: a valid utility emits; an invalid or unknown role value remains an ordinary class without a build diagnostic. Audit may report that role as ignored. An exact match in `authoredClasses` suppresses utility validation, generation, and utility diagnostics at every candidate origin. It cannot suppress configuration errors or stylesheet checks.

## Leftover directives and CSS command

The compiler rejects legacy engine imports and directives, including `@tailwind`, `@theme` with any modifier, `@source`, `@custom-variant`, `@apply`, `@utility`, `@variant`, `@plugin`, `@config`, and `@reference`. Imports of `tailwindcss` and its subpaths are rejected too. The old value functions `theme()`, `--spacing()`, `--alpha()`, and `--value()` in declaration values are also errors. Diagnostics name the spelling and stylesheet file and span and link to [Coming from Tailwind](./coming-from-tailwind.mdx).

The scanner ignores comments and string contents, decodes escaped CSS identifiers and import strings, and checks the authored stylesheet and every imported stylesheet before trying to resolve a forbidden import. This check still runs when `wind` is false. Ordinary `@layer` and imports that explicitly name a layer remain valid.

The standalone `zfb css` command remains the wind compiler. When generation is enabled, `--source` and `--no-auto-source` retain their source-discovery meaning, and highlight flags retain their highlighting role. With `wind: false`, the command processes authored CSS and highlighting without wind generation. The separate `zfb wind explain` and `zfb wind audit` commands provide candidate inspection and source audit.

## Generated identity

Every generated reset, token, registration, and utility rule uses the virtual source `zudo-wind://spec/1`. The source record identifies language version 1 and revision 3. V1 creates no generated source map and promises no line mapping. Candidate-to-source locations are retained in rule metadata and diagnostics instead.
