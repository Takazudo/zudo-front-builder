zfb ships ten standalone example repositories. Nine are small, deployable
projects that each demonstrate a single Cloudflare recipe end to end; the tenth,
Agent Conversations, runs locally only. Every repo is independently
`pnpm install`-able and includes its own README with local run steps, and the
Cloudflare ones also include provisioning commands — clone one to see the whole
thing assembled rather than copying snippets piecemeal.

This page is the comparison matrix. Each listed repository pins zfb 3.1.0 (checked on
2026-10-03) and uses zfb's `zudo-react` JSX runtime. The styling column shows whether it uses
zudo-wind utilities, only its reset, or authored CSS. Each row links to a full
walkthrough under [Recipes](../recipes/index.mdx), which explains what that
example demonstrates, how it works, and how to run it locally.

The nine Cloudflare examples deploy as **Cloudflare Workers** on `takazudomodular.com` subdomains.
Seven ship server code; two are assets-only Workers that serve a static build
and run no Worker script at all.

<Note title="password-gate answers 401 by design">

Every demo link below points at a deployed, live site, with one deliberate exception:
[zfb-example-password-gate.takazudomodular.com](https://zfb-example-password-gate.takazudomodular.com/)
answers `401 Unauthorized` with a login page instead of showing you a site.
That is the example working — gating the content is its entire point.

</Note>

## Worker-backed examples

These seven emit or hand-write a Worker script that runs on every request they
own. Six use `@takazudo/zfb-adapter-cloudflare` to run `prerender = false`
routes — the pattern covered in
[SSR and Cloudflare Bindings](./ssr-and-cloudflare-bindings.mdx). The seventh,
`password-gate`, installs no adapter and puts a Worker of its own in front of a
static build.

| [JSON API](../recipes/json-api.mdx) | SSG plus two `prerender = false` API routes (adapter) | none | Authored CSS; zudo-wind reset only | [repo](https://github.com/Takazudo/zfb-example-json-api) · [demo](https://zfb-example-json-api.takazudomodular.com/) |

## Static examples

These two deploy the `dist/` directory as **Workers Static Assets** with no
Worker script: `wrangler.toml` carries an `[assets]` table and deliberately no
`main` key, and `@takazudo/zfb-adapter-cloudflare` is not a dependency. They are
the shape to copy when a site needs no server code at all.

| Example | Rendering | Bindings and secrets | Styling | Links |
| --- | --- | --- | --- | --- |
| [Blog](../recipes/blog.mdx) | Pure SSG, assets-only Worker | none | Authored CSS; zudo-wind reset only | [repo](https://github.com/Takazudo/zfb-example-blog) · [demo](https://zfb-example-blog.takazudomodular.com/) |
| [Corporate Website](../recipes/corporate-website.mdx) | Pure SSG, assets-only Worker | none | CSS Modules; zudo-wind disabled | [repo](https://github.com/Takazudo/zfb-example-corporate-website) · [demo](https://zfb-example-corporate-website.takazudomodular.com/) |

## Local-only example

This one has no deployment. Its public showcase is a static zfb build, and a
second build of the same UI talks to a loopback HTTP and SQLite server. It also
contains a Cloudflare Worker handler factory, but no Worker, D1 database, or
Queue has been provisioned, so do not read it as a deployed Cloudflare
application.
