# zfb v3 migration guide: zudolab/zzmod

Generated 2026-10-04 by an automated diagnosis of `develop` @ `8f46920`. Counts come from the commands listed; re-run them locally before relying on them.

## Verdict

**Blocked (XL).** zzmod is five coupled zfb hosts that share one Preact + Tailwind source graph, not five independent sites. The root site, `sub-packages/ui-preact` and `sub-packages/zmdpreview` could start on zfb 3.1.0 today, but `doc/` and `sub-packages/styleguide` cannot finish until **zudo-doc 6.0.0** ships (zudolab/zudo-doc#4430, root PR #4477), and the styleguide is additionally gated on a v3-compatible **zudo-sg** (npm `latest` 0.4.1 still pins zfb 2.21.1) or a decision to port the vendored catalog by hand. Because the styleguide type-checks and renders the root's `*.stories.tsx` (137 story modules import the `ui-preact` story contract), the root cannot be converted to zudo-react without breaking the styleguide, so the whole graph has to move on one coordinated, non-shipping branch. Effort is XL on raw counts alone: 72 `'use client'` island files (58 root graph, 13 styleguide, 1 doc), 58 `<Island>` call sites, ~960 hook calls, 6 `createPortal` dialogs, ~350 camelCase DOM listeners (of ~600 `on*=` attributes), 1,482 `className=` attributes in TSX plus 454 in MDX content, 232 `@theme` tokens, 19 `@utility` blocks, 3 hand-rolled Tailwind compilers in the styleguide, and 5,354 error-severity `zfb wind audit` diagnostics on the root alone. **No migration branch or PR exists** — the only artifact is issue zudolab/zzmod#2931 (open), whose stage-2 pilot code lives in an uncommitted ChatGPT ZIP. The user's belief that a WIP migration PR exists is wrong; PR #2906 (`base/styleguide-engine-260923`, draft, 150 files, `mergeable_state: dirty`) is the *zudo-sg 0.3.6 on zfb 2.20.3* adoption and is orthogonal; its blocker Takazudo/zudo-sg#866 was closed `not_planned` on 2026-09-25 and the PR's last CI comment still reports the styleguide build failing, so it is stalled rather than progressing.

2. **Now, but on a non-shipping branch:** root site + `ui-preact` + root stories to zudo-react. The styleguide on that branch is red until step 4 — accept that and gate CI accordingly (see §5).
3. **Blocked on zudo-doc 6.0.0** (zudolab/zudo-doc#4430 / #4477; 39/51 topics merged only in the maintainer's local base as of 2026-10-02; integration floor #4467 waits for zfb bugs #3569/#3570, fixed on zfb `main` 3981f6e but unreleased): `doc/` and the styleguide host shell (`zudoDocPreset`, `@takazudo/zudo-doc/*` route imports, `safelist.css` → the planned `wind.json` manifest, `zudoDoc({ wind })` override). 4. **Blocked on zudo-sg** (Takazudo/zudo-sg, pins zfb 2.21.1, npm 0.4.1): either a v3-compatible `@takazudo/zudo-sg` release (then finish PR #2906's adoption on top of it) or a hand port of the vendored `sub-packages/styleguide/src/styleguide/**` catalog to zudo-react. ## Risks and open questions

- **Portal/dialog ownership** (6 files) is a product decision, not a mechanical port; `<dialog>` top-layer changes stacking relative to `z-dialog-backdrop`/`z-dialog-panel` tokens and the styleguide's embedded (`portalContainer`) story mode.
- **Styleguide double block**: zudo-doc 6.0.0 *and* zudo-sg v3. If zudo-sg lags, the vendored catalog port is ~40 ts/18 tsx files plus three CSS generators and 42 tests; PR #2906's 150-file zudo-sg adoption would then be abandoned or redone.
- **Cascade regressions**: 50 `group-hover:*` sites lose specificity; unlayered authored link rules (`styles/global.css:249`) now lose equal-specificity ties to utilities unless `placement: "before-authored"` (**next zfb release**).
- **Bare-specifier CSS imports** (`@import '@takazudo-modular/design-system'`, `/palette`, `/tokens`, `@takazudo/zdtp/styles.css`) resolve through package `exports` since 3.1.0 (#3364) but are untested in this repo; run `zfb css` on the pinned version before the CSS cut-over.
- **Source-root gap on 3.1.0**: `sub-packages/ui-preact/src`, `lib/` and the styleguide's repo-root `@source` globs are not scanned by zudo-wind until `wind.sources.packageRoots` ships; the interim manifest/safelist must be kept in sync by hand or ui-preact components silently lose their utilities.
- **Audit noise**: ~12,400 ZW001/ZW005 `auditInfo` entries come from URL/path/label strings in tests/stories (~3,980), data modules (~3,300), page/lib modules and MDX; without `wind.sources.exclude` (**next zfb release**) `--fail-on error` still works because those are audit-only, but reports stay long (the root report is 28,941 lines). The 417 error-severity ZW001/ZW005 hits (§2) are real and must be fixed.
- **Dynamic class maps**: 1,216 ZW012 hits, dominated by non-class string building (`src/components/web-synth/doc/parse.ts` 121, `case-builder/case-3d/net-folding.ts` 53, `components/mdx/patch-demo/patch-engine-runtime.ts` 37, transform/`calc()` strings in `web-synth/patcher-surface.tsx` 29 and `guides-landing/guides-filter-island.tsx` 44); the class-relevant ones are the `ellipsis-` prefix in `components/list/pagination.tsx`, `src/components/shared/pagination.tsx` and `src/components/products/filtered-pagination.tsx` — convert to complete literals or an owner-keyed `wind.safelist`. `metamodule-ref/layout-classes.ts` is static (its problem is the ZW004 attribute variants above).
- **Bundle size**: zudo-react makes no Preact-parity promise; measure `dist/assets/islands-*.js` before/after.
- **Stale pilot baseline**: #2931's hash-verified upstream fixtures target zfb `8219310` (3.0.0); re-run its 65 Node + 16 Chromium checks against the installed 3.1.0 / next release before integrating.
- **No branch exists yet**: the planning (issue opened 2026-09-29, stage-2 handoff 2026-09-30) lives in an issue and a ZIP outside git; step 1 fixes that.
