## Risks and open questions

- **Public API break**: dropping the `preact` peer and changing the JSX runtime is breaking for every generated project; pre-1.0 Scheme B makes it 0.3.0, and the initializer must follow (`dev-docs/publishing.md`). Consumers cannot mix: a 0.2.0 host on zudo-doc 5 cannot take 0.3.0, and vice versa. State the pairing in both changelog lanes and in `templates/default/ZUDO_DEPS_PINS.md`.
- **`useModalDialog` dependency**: the dialog's whole lifecycle comes from zudo-doc; the planned 6.0 export is `modalDialog(scope, options)` (zudolab/zudo-doc#4473), unreleased. If 6.0 ships without it, the package must own a small setup-scope helper (showModal/close sync, native `close` listener, backdrop click, `AFTER_NAVIGATE_EVENT` close, focus restore) — about 60 lines, but it needs the 6.0 event-name exports (`/transitions`) to remain public.
- **Scaffold parity gate**: `check-upstream-scaffold.mjs` hard-codes 5.27.0's feature list and allows exactly two additions; any new 6.0 host-glue line (for example a wind config block) must be added to its allowlist or the gate stays red.
- **Theme token names**: 22 distinct zudo-doc custom properties in `styles.css`; a rename in 6.0 silently degrades every record page. Diff `theme.css` 5.27 → 6.0 before building.
- **`fixtures/led` is frozen** (hash-locked, zudo-led-lamp @ `194d8a2`); it is a corpus, not a host, so it needs no migration, but `EXPECTED-CHANGES.md` must record any generated-output difference the port introduces (none expected: no class names in MDX).
- **BEM `__` names**: safe as long as no host declares the package in `wind.sources.packageRoots`; otherwise 22 ZW001 errors on 3.1.0 until the next zfb release.
- **Three identical copies**: `examples/empty`, `examples/minimal`, template — only `examples/empty` is hand-edited (`sync:template`), and `examples/minimal` must be updated by hand in step; a missed copy fails `ci-examples.yml` late.
- **Attribute-order assertions** in `test/ui/ssr.test.ts` and any snapshot in `test-led/**` will change with the renderer; review diffs rather than blindly re-baselining.
