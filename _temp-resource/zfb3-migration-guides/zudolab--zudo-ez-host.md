- **R3: token-name collisions** between the app (`bg`, `fg`, `muted`, `accent`, `focus`, `border`, state colors, `code-*`) and zudo-doc's vocabulary. Host `wind.tokens` overrides the preset's values; declare only app-only names and keep relying on the `[data-zeh-sample]`-scoped generated CSS for the rest.
- **R4: `styleguide/ui/` is not a conventional root** in 3.1.0; without `wind.sources.packageRoots` (**next release**) or relocation, story classes are neither validated nor generated for the inline thumbnails' host chrome.
- **R5: `plugins/highlight-assets.mjs`** depends on the 2.20.4-era gap (no `?url` loader in the module-worker esbuild pass) still existing in v3; the plugin hooks it uses are unchanged (https://zfb.takazudomodular.com/concepts/plugins/), so a v3 `zfb build` with the plugin removed is the first thing to try, and `/preview/highlighting` (47 semantic spans, `docs-internal/baseline.md`) is the acceptance check either way.
- **R6: utility placement flip.** Wind emits utilities after authored CSS by default; the styleguide's unlayered `.zd-content > table` rule (`global.css:43-47`) and the scoped generated CSS were written for Tailwind's utilities-first order. Scoped rules keep winning by specificity; the table rule should be checked. `wind.utilities.placement: "before-authored"` is **next release** (https://zfb.takazudomodular.com/zudo-wind/coming-from-tailwind/#utility-placement-and-ties).
- **R7: hydration semantics.** Islands hydrate fail-closed and the DOM value wins for form controls (https://zfb.takazudomodular.com/zudo-react/hydration/); the preview demos with in-memory stores (`_appearance-demo.tsx`, `_projects-pull-all-demo.tsx`) need their first render deterministic.
- **R8: pin drift.** Until the hold rule exists, a routine `/dev-bump-zudo-deps` run moves `@takazudo/zfb` to 3.1.0 and breaks all three hosts at config load (`zudoDoc()` still emits `framework`/`tailwind`).
