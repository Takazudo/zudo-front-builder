summary: ANSWERS TO THE 6 QUESTIONS (all verified in code at HEAD 43d87ba0; the handoff snapshot 95d06aea differs from HEAD in this area only in livereload tests: `git diff --stat 95d06aea..HEAD` over crates/zfb-islands, packages/zfb, packages/zfb-runtime, tests/router-chromium, tests/webkit-back-history, tests/built-site-smoke, crates/zfb-render/src/adapters = 2 files, both livereload-only).

(1) MOUNT CONVENTION. `type IslandMount = (props: Record<string,unknown>, element: Element, mode: "hydrate"|"render") => void` and `type IslandUnmount = (element: Element) => void` (packages/zfb/src/runtime.ts:273-285). Module may export `mount` or `default`; `unmount` optional. mount's RETURN VALUE IS DISCARDED. The runtime stores only an unmount thunk `() => mod.unmount(element)` in module-private `mounted: WeakMap<Element, () => void>` (runtime.ts:359, set at :685 and :771). Root handles today live in GENERATED GLUE, not the runtime: React arm uses module-scope `const __zfb_roots = new WeakMap()` (esbuild.rs:2831 shared, :3025 per-island); Preact arm stores nothing and unmounts with `render(null, element)` (esbuild.rs:2896, :3004). Three viable storage slots for a zudo-react root/disposer: (a) glue-side WeakMap mirroring the React arm (zero runtime.ts change); (b) widen IslandMount to return a handle and store it in `mounted`; (c) an element expando/Symbol.for key, the only option that survives a re-imported module instance (dev livereload re-imports the islands bundle with `?v=<ts>`, crates/zfb-server/src/livereload.js:60-101, creating a fresh `mounted` map over already-activated DOM).

(2) SSR MARKER FORMAT. Emitted by the JS `<Island>` wrapper at SSR time, not by Rust: `<div data-zfb-island="Name" data-when="load|idle|visible|media" [data-media="q"] [data-props='json']>…SSR children…</div>`; SSR-skip variant `<div data-zfb-island-skip-ssr="Name" …>fallback</div>` (island.ts:150-179). Runtime-added attrs: `data-zfb-island-mounted=""` (runtime.ts:353), `data-zfb-island-remount=""` (swap-functions.ts:31). No schema version, protocol version, build id or root id exists. IDENTITY = a bare name string matched two ways: SSR side computes `type.displayName ?? type.name` at render time in V8 (island.ts:278-290), falling back to the host tag string or "Anonymous"; client manifest key is `Island::marker_name`, a STATIC literal the Rust scanner derives from the AST (bundler.rs:58-96, scanner.rs:3631-3660) and bakes into the entry via `__zfb_register(ns, exportName, markerName, moduleLabel)` (esbuild.rs:2939-2949). So the client side is already minification-proof; the SSR side still reads a runtime function name. The scanner does not read `displayName` assignments, so a displayName-renamed component mismatches; `island_marker_check` only WARNS at build (build.rs:7188).

(3) PROPS SERIALIZATION. `JSON.stringify` of the child VNode's `props` minus `children` into the `data-props` attribute (island.ts:322-366). Silently lost: `children` always (:343); function/symbol/undefined values (dropped in objects, `null` in arrays); the ENTIRE payload when stringify throws (cycles, BigInt) via an empty catch (:350-358); payload omitted when result is `"{}"` (:364). Silently mangled rather than dropped: Date→string, Map/Set→`{}`, NaN/Infinity→null, class instances→plain objects, JSX-valued props→serialized VNode internals. With array children only the first child with non-empty props is used, chosen independently of the first child with a name, so name and props can come from different children. Client side `readProps` maps missing/invalid JSON/array to `{}` silently (runtime.ts:867-884).

(4) PERSIST + REMOUNT AS IMPLEMENTED. `unmountIslands(root, incomingBody)` skips an island iff the island element ITSELF carries `data-zfb-transition-persist` whose id exists in the incoming body (runtime.ts:836-848; direct getAttribute, no closest()). `swapBodyElement` lifts the node, then flags remount iff `newTarget.matches("[data-zfb-island]") && shouldCopyProps(el) && !isSameProps(el,newTarget)` where isSameProps is `data-props` STRING equality only (swap-functions.ts:205-215, :333-341). `data-zfb-transition-persist-props` absent or "false" = refresh props; any other value = keep old props, no remount. `mountNewIslands` → `clearMountedForRemount` runs the old unmount thunk, deletes the map entry, strips both attrs, then force-mounts bypassing the scheduler WITH MODE "hydrate" (runtime.ts:454-456, :498-516). Skip-SSR islands never get the flag. A changed COMPONENT NAME with equal props is not detected. `<Island>` has no persist prop, so persisted islands are hand-authored marker divs (documented at docs/src/content/docs/concepts/client-side-routing.mdx:513-530).

(5) HARNESS REUSE. Not as-is. There are FOUR Playwright harnesses, not two. tests/router-chromium and tests/webkit-back-history serve hand-written static HTML plus `packages/zfb-runtime/dist` and replace `@takazudo/zfb/runtime` through an import map with `island-stubs.js` (no-ops) or `island-real.js` (a hand-written counter); neither loads packages/zfb/src/runtime.ts, any framework, or any SSR output. tests/built-site-smoke is the only one that loads real `zfb build` output with a real Preact island and already has a held-module pre-hydration window (hydration.chromium.spec.mjs:60-84) that is directly reusable for node-identity assertions, but it needs a built zfb binary from CI. A new runtime-only tests/zudo-react-browser harness is roughly 5 files + 1 workflow + 1 root script, and can avoid cargo entirely by building with tsc.

(6) OUTPUT MODES. Only the SHARED bundle is live. `zfb build` and `zfb dev` both go through `build_production_islands_asset` → `ClientBundler::bundle` → `render_shared_bundle_entry_source` with `--splitting=true` (build.rs:4749, dev.rs:4135 rebundle_islands, esbuild.rs:1088-1095). `bundle_per_island` / `render_island_entry_source` / `render_runtime_entry_source` have zero callers outside zfb-islands tests and the source says "this path is not production-wired" (esbuild.rs:1174-1175). The URL-string manifest branch of runtime.ts (dynamic import, `pending` set) is therefore exercised only by vitest.

## contracts
  - Browser mount contract: mount(props: Record<string,unknown>, element: Element, mode: "hydrate"|"render"): void; unmount(element): void; module exports mount|default and optional unmount (packages/zfb/src/runtime.ts:273-285). Return value of mount is ignored.
  - Manifest contract: IslandManifest = Record<markerName, string URL | IslandModule inline object> (runtime.ts:307-308). Production passes inline objects only.
  - Marker attribute contract (public, hand-authorable, documented): data-zfb-island, data-zfb-island-skip-ssr, data-when, data-media, data-props, data-zfb-island-mounted (observational only, never a guard), data-zfb-island-remount, data-zfb-transition-persist, data-zfb-transition-persist-props.
  - Cross-package literal-string contract: PERSIST_ATTR and ISLAND_REMOUNT_ATTR are duplicated as string constants in packages/zfb/src/runtime.ts:315,321 and packages/zfb-runtime/src/client-router/swap-functions.ts:15,31 plus router.ts:179; the DOM attribute is the only channel between the two packages.
  - Router call order contract: cancelPendingIslands() then unmountIslands(document.body, incomingBody) inside the synchronous swap commit; mountNewIslands() after runScripts() and before zfb:page-load (router.ts:634-638, 1001).
  - Scheduling contract: load = synchronous fire; idle = requestIdleCallback or setTimeout(0); visible = IntersectionObserver threshold 0 then disconnect; media = matchMedia on data-media, fires on first match; every missing browser API fails OPEN to immediate fire; mode "render" (skip-SSR) and forced remount ignore data-when (runtime.ts:47-69, 703-714, 775-783).
  - Guard contract: mounted map + pending set checked at schedule time and again at fire time; isConnected checked before mount; inline path has no pending window.
  - Error contract as implemented: a throwing inline mount propagates synchronously out of mountIslands/mountNewIslands and aborts the walk over remaining islands for when=load; pinned by test `expect(() => mountIslands({ Throws: { mount } })).toThrow(...)` (packages/zfb/src/__tests__/runtime.test.ts:1596-1613).
  - Generated entry contract: shared entry imports `mountIslands` from "@takazudo/zfb/runtime", optional side-effect import "@takazudo/zfb-runtime/client-router", one `import * as __zfb_island_{i}` per island, `__zfb_register(...)` per island, final `mountIslands(__zfb_manifest)` (esbuild.rs:2801-2950). Output must be byte-deterministic for a given (islands, config).
  - Single-source-of-truth contract: BundleConfig::jsx_import_source drives BOTH the esbuild --jsx-import-source flag and the glue framework via FrameworkKind::from_jsx_import_source (esbuild.rs:1083-1088).
  - Bundle output contract: entry stable name islands.js, chunks islands-chunk-<hash>.js flat and never renamed; bytes carried in memory, downstream owns disk writes (bundler.rs:510-586).
  - Component-shape guard: only `typeof C === "function"` or an object with `$$typeof` is registered (esbuild.rs:2664-2668). zudo-react function components pass; `$$typeof` is React/compat-specific.
  - SSR adapter contract that touches this area: zfb_render Adapter requires hydrate_shim_specifier/hydrate_shim_source exporting hydrateIsland (crates/zfb-render/src/adapters/mod.rs:110-122); the shim is written into the SSR shadow and re-exported from the SSR bundle (crates/zfb-build/src/bundler.rs:4824-4825, 12227, 12310).
