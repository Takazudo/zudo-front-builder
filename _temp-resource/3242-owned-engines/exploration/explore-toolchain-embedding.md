subsystem: Toolchain pins, binary staging (esbuild + Tailwind), and embedded JS packages (build.rs -> $OUT_DIR/vendor -> include_dir! -> runtime extraction)
summary: ONE embed pipeline serves everything: crates/zfb/build.rs stages three groups into $OUT_DIR/vendor/ — (1) first-party TS source `@takazudo/{zfb,zfb-runtime}` copied from packages/*/src (only `*.ts`, skipping `__*` and dot entries) + package.json; (2) published trees of preact 10.29.1, preact-render-to-string 6.6.7, hono 4.12.25 copied from node_modules/.pnpm (so `pnpm install` is a hard prerequisite of `cargo build`); (3) `bin/esbuild` + `bin/tailwindcss-v4` downloaded/SHA-verified into crates/zfb/binaries/ slots then copied to vendor/bin. `static EMBEDDED_VENDOR = include_dir!("$ZFB_VENDOR_DIR")` (render_pipeline.rs:112) embeds the whole tree uncompressed. Runtime: `embedded_binary(name)` extracts one bin to a tempdir; `embedded_node_modules()` extracts everything except `bin/` as a `node_modules/` tree.

KEY FACTS THE PLAN MUST BUILD ON:
(a) The embedded JS tree is used ONLY when `<project_root>/node_modules` does not exist (bundler_input.rs:316-344 for SSR; commands/build.rs:4587-4606, ~5862, ~6556 for islands/client scripts). Any consumer with a node_modules dir (basic-blog template, docs, scaffold E2E) resolves the framework from ITS OWN node_modules. Embedding zudo-react therefore covers only the node-free path.
(b) The embedded V8 host resolves NO bare package specifiers. BundleModuleLoader (module_loader.rs:380-425) handles only node:* stubs, ext:, plugin aliases (exact match), virtual modules, in-memory file:// and copied .wasm. SSR works because esbuild inlines preact + preact-render-to-string into bundle.mjs (`--bundle --platform=neutral`, `external` default empty, bundler.rs:799). So "resolvable by the V8 SSR host" == "resolvable by the SSR esbuild pass"; no V8 loader change is needed.
(c) SSR resolution in node-free mode = `<shadow>/node_modules` symlink to the extraction + `--preserve-symlinks`; client resolution = `NODE_PATH=<extraction>` env on the esbuild subprocess. Two different mechanisms, both fed by the same extraction.
(d) Tailwind is coupled at COMPILE time, not just runtime: build.rs emits `cargo:rustc-env=ZFB_EMBEDDED_TAILWIND_SHA256` and css_support.rs:119 + render_pipeline.rs:2298 consume it via `env!`. Removing the stamp without removing those sites breaks compilation of the zfb crate.
(e) build.rs never purges $OUT_DIR/vendor (no remove_dir_all anywhere in the file) and OUT_DIR is reused across build.rs edits, so a removed package/binary stays embedded in incremental and rust-cache-restored builds unless a purge step is added.
(f) docs/ is NOT a consumer of the workspace binary: it pins published `@takazudo/zfb` 2.20.2 (workspace is 2.22.0) and CI builds it with `pnpm install && pnpm --filter docs build`, no cargo.

## contracts
  - Vendor layout contract: $OUT_DIR/vendor/{@takazudo/zfb,@takazudo/zfb-runtime,preact,preact-render-to-string,hono,bin/{esbuild,tailwindcss-v4}[.exe]}; ZFB_VENDOR_DIR rustc-env points at it; include_dir! embeds all of it.
  - First-party embed contract (embed_runtime): copies `package.json` verbatim + `src/**` files whose name ends with `.ts`, skipping any entry starting with `__` or `.`. `.tsx/.js/.mjs/.json/.css` are dropped silently. Embedded packages resolve through the SOURCE manifest's `exports` (-> ./src/*.ts), never publishConfig.
  - Third-party embed contract (embed_framework_packages): package must exist at node_modules/.pnpm/<name>@<version>[_peer-suffix]/node_modules/<name>; version constant in build.rs must equal the lockfile; panics with remediation text otherwise. Skips nested node_modules, test dirs, dotfiles, *.map.
  - embedded_binary(name) -> (TempDir, PathBuf): caller must keep TempDir alive for the subprocess lifetime; probes bin/<name> then bin/<name>.exe on Windows.
  - Binary precedence (both tools): explicit config path -> ZFB_*_BIN env (empty == unset) -> embedded extraction -> workspace slot crates/zfb/binaries/.
  - Build-time override contract (BUILDING.md): ZFB_ESBUILD_BIN / ZFB_TAILWIND_BIN must be absolute paths to regular files; SHA pinning skipped; each binary resolves independently; Unsupported target + no override = hard build error.
  - node_modules selection: `<project_root>/node_modules` is a dir -> use it, embedded tree ignored entirely; else embedded extraction with node_modules_preserve_symlinks=true (SSR) / NODE_PATH (client). Islands additionally accept first_party_root_for(project_root)/node_modules.
  - Adapter contract (zfb-render Adapter trait): jsx_import_source() feeds synthetic tsconfig jsxImportSource, islands --jsx-import-source, and the staged-dependency seed; render_to_string_module() is imported in generated entry.mjs as `import { renderToString as __zfb_renderToString } from <spec>` — the module MUST export a function named `renderToString`.
  - V8 loader contract: bundle must be self-contained; only node:*, ext:, plugin alias (exact), virtual module, in-memory file://, and bundle-relative .wasm are loadable.
  - Tailwind digest contract (#3159): build.rs hashes the STAGED copy and stamps ZFB_EMBEDDED_TAILWIND_SHA256; consumed via env! at compile time; first 16 hex chars name the $TMPDIR warm-up marker `zfb-tailwind-oxide-warmup-<key>.done`.
  - CI staged-binary cache key: `zfb-staged-binaries-v1-<target>-hashFiles('crates/zfb/build.rs','crates/zfb-toolchain-pins/src/lib.rs')`, no restore-keys — every edit to either file invalidates the cache and forces a fresh download of BOTH binaries in every job carrying the step.
  - Publish-list contract (CLAUDE.md + drift guard): every non-private package under packages/* or crates/*/npm must be in PUBLISHED_PACKAGES and advance-latest-dist-tag.sh; ten packages in lockstep; five changelog lanes.
  - `#[ignore]` manifest contract (crates/CLAUDE.md): adding/removing any ignored test requires updating the manifest table, exam.yml exact-name filterset / health.yml lanes in the same change; scripts/check-exam-ignore-parity.sh enforces it.
  - `zfb new` rewrites any `workspace:*` dep in a template package.json to `=<binary version>` (new.rs:81, 308-316).
