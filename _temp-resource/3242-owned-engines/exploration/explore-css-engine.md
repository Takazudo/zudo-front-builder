subsystem: CSS engine boundary (crates/zfb-css + its command-layer callers in crates/zfb/src/commands/{build,css,css_support,dev}.rs)
summary: zfb-css is 11,250 lines (src 9,947 incl. tests). The engine boundary is one trait with 2 methods (`produce_utility_css(&self, &[PathBuf]) -> Result<String>` + default-impl `take_package_url_companions`), 3 implementors, and exactly ONE production `CssPipeline::new` site (css_support.rs:201, via `build_emitter()`; the disk-writing `CssPipeline::build()` has only test callers). Engine selection is a single bool: `config.tailwind.enabled` branched at build.rs:1186-1196 inside `build_default_css_payload_with_source_plan`, which BOTH `zfb build` (build.rs:933) and `zfb dev` boot+tick (dev.rs:4656, 2537-2583) funnel through. `zfb css` (css.rs:123-128) bypasses the selector and always constructs Tailwind. `NativeRustEngine` is constructed nowhere in production (only tests/integration.rs:24).

All three implementors IGNORE the `sources` argument (`_sources`); `sources` only feeds CSS Modules auto-discovery (pipeline.rs:273-295). Tailwind learns its scan set from a synthesised temp entry CSS (`zfb-tailwind-entry-XXXXXX.css` written next to global.css) carrying `@source` directives.

Import/asset behaviour today is split three ways: (a) on the Tailwind path `@import` flattening + package specifier resolution happen INSIDE the Tailwind CLI; (b) relative `url()` handling is zfb code (url_scanner.rs + url_attribution.rs) but is 100% dependent on Tailwind's `--map` inline sourcemap for provenance and fails closed without a map; (c) on the `tailwind.enabled=false` path zfb already has a Tailwind-free flattener, `bundle_authored_css` (Lightning CSS `Bundler` + custom `SourceProvider`, css_imports.rs:124-153), but that path emits NO url() companions at all (AuthoredCssEngine inherits the empty default). A separate Rust import-graph walker `resolve_css_imports` exists only to produce watch targets / authored-path sets (dev.rs:4627, bundler_input.rs:598).

No final-stylesheet minifier exists: Tailwind minify flags are hard-rejected (engine.rs:1279-1321); only CSS Modules are minified (modules.rs:224). No file in this area changed between the handoff snapshot 95d06aea and HEAD (`git diff --stat` over zfb-css, css commands, build.rs, toolchain-pins, zfb-build/src/pipeline is empty), so handoff errors here are omissions, not drift.

Cleanest seam: new pure crate crates/zudo-wind + a `ZudoWindEngine` adapter in zfb-css replacing native_engine.rs, selected by a new 3-way enum resolved from config at build.rs:1186; authored global.css goes through the existing `bundle_authored_css`; url() provenance must be re-sourced (Lightning bundler source map or per-file pre-resolution) because the Tailwind sourcemap disappears.
