subsystem: build/dev orchestration around CSS and incremental rebuilds (zfb build / zfb dev / zfb css, zfb-build orchestrator+policy, zfb-watcher, livereload)
summary: HEAD measured at 16bd41a8 (9 commits past handoff snapshot 95d06aea; task text said 43d87ba0). CSS is produced by ONE command-layer function, build_default_css_payload_with_source_plan (crates/zfb/src/commands/build.rs:1064), shared by `zfb build` (DefaultRunner::emit_prod_assets, build.rs:933) and `zfb dev` (boot pass dev.rs:2507 + per-tick `run_css` closure dev.rs:2537-2583). Every call is a FULL recompute: it constructs a fresh TailwindSubprocessEngine (build.rs:1271), re-walks all roots, recomputes SiblingMirrorPlan twice, and spawns the Tailwind CLI. There is no session-lived CSS engine object and no persistent CSS cache; 'warm' state exists only conceptually in a dev session.

There is NO normalized source-plan type. 'Source plan' today = (1) `CssSourcePlanObserver = &dyn Fn(&[PathBuf])` (build.rs:986), a callback carrying only sibling mirror-root directories; (2) four uncoordinated channels feeding Tailwind: string globs on TailwindSubprocessConfig (content_globs / negative_source_globs / framework_package_globs / inline_sources, engine.rs:144-196), user-authored `@source` lines inside global.css (rebased, engine.rs:571), package-shipped `@source inline(...)` safelists, and Tailwind's AMBIENT auto-detection which stays ON for build/dev (explicit_sourcing only set by `zfb css`, css.rs:128); (3) a separate `sources: Vec<PathBuf>` file list (discover_css_source_files, build.rs:1651) that the Tailwind engine IGNORES (`_sources`, engine.rs:1402) and only CSS-Modules import scanning consumes. Three different root lists exist: DEFAULT_CONTENT_ROOTS (5, engine.rs:1922), DEFAULT_WATCH_ROOTS (9, dev.rs:145), policy classifier segments (policy.rs:1034-1050).

Dev CSS triggering is a single boolean RebuildPlan::rerun_css (plan.rs:59) and the runner is `CssRunner = Arc<dyn Fn() -> Result<bool>>` (pipeline/mod.rs:272) taking NO arguments: changed/removed paths never reach the CSS pass. rerun_css is set for: PathClass::Style, PathClass::Module (unconditional, #1288), Global, plugin watch targets, and Content/Data/External ONLY under a registered css mirror root. It is NOT set for in-root Page edits (pages/*.tsx), in-root Content edits (content/*.mdx), or ANY in-root deletion of Page/Module/Content/Data (orchestrator.rs:1543-1550, documented gap 1577-1584). These negatives are pinned by tests. So today a utility class newly authored in an in-root page or MDX file is not emitted in dev until some Module/Style edit happens, and a deleted source never retracts classes until then.

Watcher: ChangeKind has 3 values; rename events classify as Modified and are reconciled at flush against on-disk existence (old path -> Removed, new path -> stays Modified, never Created). macOS can deliver an in-place edit as Created; a created directory's children may never surface; Removed+Created can share a tick. A native engine must therefore use existence-keyed upsert/remove by source ID and never trust Created-vs-Modified.

Livereload: BuildOutcome.css_changed -> ReloadEvent::Css -> client swaps every link[rel=stylesheet] href with ?v=ts. Transport is now WebSocket (changed after the handoff snapshot). publish_dev_css_generation always returns Ok(true) on success, so a Css event fires on every CSS rerun even when bytes are identical.

## blastRadius
  - Dev-loop cost on content-heavy sites: forwarding every content edit to the CSS engine reverses a deliberate decision (orchestrator.rs:3815-3845). Safe only if the per-file rescan is cheap and the Tailwind path keeps today's gating.
  - Aggregate-page rendering: any edit near plan_for_changes risks the PageSelection::All fallback that is the only thing re-rendering aggregate pages (lessons file; issue #1583). CSS work must not alter page selection.
  - Dynamic watch registration: css_mirror_roots uses replace semantics; publishing a narrower set unwatches live roots (build.rs:1110-1135). A SourcePlan that replaces this registry must keep 'skip publication on failure'.
  - Revert-proof masking: a sibling directory can be claimed by both dynamic-watch channels; new confirm e2es must use a path claimed only by the channel under test (lessons file).
  - Workspace/sibling consumers: classes used only in claimed sibling packages, root-package files, or package-route pages reach Tailwind through assemble_css_content_globs; dropping any channel yields a green build with missing styles.
  - Consumers relying on ambient detection: classes in lib/, utils/, data JSON, zfb.config.ts, or collections outside the 5 default roots are found today only by Tailwind's ambient scan or authored @source lines.
  - CSS Modules scoped-name parity: compute_css_module_class_maps and run_css_emitter must keep the same hash root (build.rs:1799-1804); changing source discovery affects which .module.css files are compiled.
  - Asset hash and HTML: prod stylesheet name derives from hash_8 over the three CSS pieces; any output change renames the asset and changes every page's link tag (affects render_artifact_* byte-identity tests).
  - embed_v8 cfg boundaries in build.rs/dev.rs: inserting functions between a doc comment and a cfg-gated fn silently moves the gate; b4push does not run the no-v8 lane (lessons file).
  - CI manifests: adding/removing any #[ignore] or test binary requires lockstep edits to crates/CLAUDE.md, .config/nextest.toml, exam.yml filterset; scripts/check-exam-ignore-parity.sh fails otherwise. 18 tailwind env-gate tests are affected at W4.
  - Intake suppression: the Tailwind temp-entry predicate (dev.rs:2327) becomes dead once no temp file is written; removing it early re-introduces self-triggered ticks while Tailwind still runs.
  - Livereload: more CSS passes means more Css events unless byte-equality suppression is added; every open tab re-fetches stylesheets.
  - Scaffold templates and docs site: crates/zfb/templates/basic-blog (8 files reference Tailwind, incl. @custom-variant and @theme in styles/global.css) and docs/src/styles/global.css depend on Tailwind directives.
