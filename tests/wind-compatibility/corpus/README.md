# Independent Wind compatibility corpus (#3831)

The checked manifest imports selected behavior from Tailwind CSS `v4.3.2` source tag commit `056a1550721d4bf79ff732d5ab9414fa83f7064f`. Its source archive is SHA-256 `1d73680e19488b19e97ea3c96722e363cc0c4fd118af546857d8703e8f0f9be3`; the npm compiler is the separately pinned `tailwindcss@4.3.2` tarball. The tag-to-package link is **unverified**. Each imported case names the immutable upstream path, test identity and original input. The fixture keeps selected candidates and records why its DOM/configuration differs. Tailwind's MIT license is copied in `LICENSE.tailwindcss` and checked byte-for-byte against the archive at execution.

The corpus has 15 existing pilot cases, 4 empty-token supplemental cases, 18 empty-token native declaration guarantees and 17 imported upstream cases with 40 DOM probes. Chromium executes 54 case obligations plus 5 CSS mutations, 10 seeded/permanent candidate permutations, 6 seeded arbitrary width values and 6 seeded HTML source strings. Firefox and WebKit each execute the same 15 pilot cases plus 10 targeted imported cases, for 54 Chromium, 25 Firefox and 25 WebKit case obligations (104 total). Each engine also executes all 11 pilot controls and 3 extraction fixtures; these controls and extraction rows are separately counted, not extra case obligations. The 18 native guarantees assert generated Wind declarations only; browser behavior is established separately by pilot and imported cases. An imported case may contain several active/inactive probes and is counted once per engine. The manifest's `compositionObligations` maps every named mechanism to concrete pilot, imported or control probes. `targetedExecutionKeys` additionally binds each targeted browser-policy obligation to checked pilot/control evidence keys; the actual engine comes from each report. No case is counted in two lanes.

The source-inspected exact-catalog static registrations and catalog keyword/fallbackKeyword members form finite inventories. Each report lists covered and omitted row IDs/candidates; the selected corpus is not exhaustive over either inventory. Arbitrary values, source strings, numeric scales and variant chains are sampled open domains. Numeric spacing uses the explicit `0.25rem` profile, while named spacing/color use project-owned tokens. The fixed reviewed-difference memberships cover each exact CSS tree, physical/logical composition, pseudo default content and child spacing. Changing a membership, disposition, count or required probe fails validation.

From the repository root after a pinned reference cache and a verified Wind example build exist, run the full pilot and corpus for each browser engine:

```sh
for engine in chromium firefox webkit; do
  node scripts/wind-compatibility/differential-runner.mjs \
    --wind-binary /absolute/path/to/wind_fixture_css \
    --wind-build-manifest /outside-checkout/wind-build.json \
    --engine "$engine" \
    --output "/outside-checkout/pilot-$engine"
  node scripts/wind-compatibility/corpus-runner.mjs \
    --wind-binary /absolute/path/to/wind_fixture_css \
    --wind-build-manifest /outside-checkout/wind-build.json \
    --pilot-report "/outside-checkout/pilot-$engine/report.json" \
    --output "/outside-checkout/corpus-$engine" \
    --engine "$engine"
done
```

Each engine's `--pilot-report` must point to a freshly rerun pilot from the **same integrated source and Wind build**. Keep its full output directory: `wind-compiler/`, `reference-compiler/`, `wind-extraction/`, `wind-native/`, `reference-native/`, and `report.json`. The importer recomputes the signed report ID; compares all 15 cases, 11 controls and 3 extraction rows to the current profile, pilot/observation/extraction/native fixtures, reference compiler, Oxide scanner, browser and adapter hashes; and checks retained CSS/report files and observed values. An older report is rejected even if its outcome fields are edited and rehashed. `--cache /absolute/path` overrides the default `/tmp/zfb-wind-reference-cache`. The runner checks the source archive and license, the eight-module pinned reference graph, Wind build identity, exact Ubuntu 24.04 x64 host, Playwright test/core versions, browser manifest SHA, browser version/revision, fixture membership and every expected engine obligation. It writes `report.json` plus the raw Wind and reference CSS, exact reference compiler input, and generated source/scanner inputs at stable per-case paths outside the checkout. Report rows carry paths and SHA-256 hashes. It exits nonzero for a missing/failed case or mutation control. Infrastructure failures get a separate `infrastructure-failure` report. A browser outside the profile matrix is unverified and exits nonzero.

The additional Chromium corpus mutation controls remove the stylesheet and a required rule, change a declaration, alter hover media, and retarget a selector. Each must turn a previously passing, byte-verified observation red. Ten fixed-seed/permanent candidate permutations compare each compiler's output against its own canonical candidate set. Six fixed-seed arbitrary widths include 0px, 1px and 17px boundaries and check exact candidate emission and computed width. Six fixed-seed HTML source strings vary class order and whitespace and compare Wind extraction with the pinned independent Oxide scanner; a failure is minimized and written outside the checkout as `shrunk-failure.json` for review and promotion into the checked `seed-regressions.json`. The existing pilot additionally checks extra rules, authored cascade, native reset, named token scope, breakpoint boundaries and physical/logical auto margins. CSS parsing preserves exact rule order, layers, selectors, custom properties, quoted strings and physical/logical names; declaration values and rule heads are compared exactly. Translation geometry permits a one-pixel window around the fixture's 16px and 8px offsets to allow fractional device rounding, while computed style assertions are exact strings. No expectation is generated from Wind output.
