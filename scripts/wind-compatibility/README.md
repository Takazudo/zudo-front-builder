# Wind reference interface (v1)

This is the test-only reference boundary for [profile 1/1](../../tests/wind-compatibility/profile.json). The initial candidate is exactly `tailwindcss@4.3.2`. It is a deliberate initial target because the existing lockfile resolves `@tailwindcss/browser@4.3.2` transitively; it is **not** a historical consumer baseline. No Tailwind dependency is added to a product or workspace manifest. The checked records at `tests/wind-compatibility/reference/{accepted,reviewed-through}.json` are separate and both remain null. The profile's `referencePolicy.initialState` is immutable bootstrap policy, not live state.

Run from the repository root with Node 24:

```sh
node scripts/wind-compatibility/reference-cli.mjs plan > /tmp/wind-plan.json
node scripts/wind-compatibility/reference-cli.mjs acquire --cache /tmp/zfb-wind-reference-cache
node scripts/wind-compatibility/reference-cli.mjs probe --cache /tmp/zfb-wind-reference-cache --candidates block,hidden,p-0,mx-auto,contents
node scripts/wind-compatibility/reference-cli.mjs assess --plan /tmp/wind-plan.json --cache /tmp/zfb-wind-reference-cache > /tmp/wind-assessment.json
node --test tests/wind-compatibility/reference/*.test.mjs
```

`plan` defaults to the explicit bootstrap candidate, never `latest`. Other versions require `--candidate X.Y.Z`; `--live yes` fetches exact npm metadata, and `--catalog /path/to/complete.json` uses an already captured complete catalog. For the bootstrap version, live/catalog metadata must match the stored package, version, SRI, tarball, SHA-1 and repository before it is normalized to the same pinned candidate with the verified artifact digest and observed tag; a mismatch fails. Plans for another version also resolve and pin its exact upstream Git tag; the tag remains a separate source observation, not an assertion that the npm artifact came from that commit. Stable is the default; `--channel prerelease` is required for prereleases on **plan, acquire and probe**. A stable version cannot be labeled prerelease. Plans state bootstrap, channel, major and prerelease transitions. A candidate must advance the accepted reference. A catalog must declare complete ordered pages with `truncated: false`, terminate with `next: null`, and contain no duplicate versions. Registry and tag errors fail closed. Use external temporary paths for captured catalog and plans. The command writes only to stdout.

`acquire` fetches the exact tarball over HTTPS, verifies its SHA-512 SRI, registry SHA-1 when given, and the embedded `package/package.json` **name and version** before writing a content-addressed copy to `--cache`. The cache must be outside the checkout. `probe` additionally extracts only compiler `.mjs` files into that cache and executes the package's own `compile`/`build` entry using `@theme { --*: initial; } @tailwind utilities;`. It emits package, SRI, artifact digest, source status, candidates and CSS. It does not use project dependencies or insert corrective CSS. The observed upstream `v4.3.2` tag points to `056a1550721d4bf79ff732d5ab9414fa83f7064f`; registry metadata has no `gitHead`, and the tag-to-tarball link has not been independently established. `packageGitSha` therefore stays null. The planning SRI hint was independently matched by the actual tarball and extracted package identity on 2026-10-06.

`assess` validates the supplied plan **against current profile, live records, command hashes, runtime, toolchain and canonical candidate metadata**. It then fetches allowlisted upstream endpoints directly. The bootstrap path reads the exact npm version metadata and SRI-verified tarball (also matching the pinned bootstrap SHA-256), the exact GitHub release body, the exact tag ref, a nontruncated recursive Git tree, and the full codeload source archive. Every archived source blob must match its Git tree SHA-1; `CHANGELOG.md` must exist. The artifact, source and test sections are derived from full archive inventories, not user-supplied item IDs. A later accepted-to-candidate assessment verifies the accepted tarball digest, reads both endpoint archives, the npm version catalog, and every GitHub release page through its `next` cursor. Missing releases, source truncation, blob mismatch, unverifiable pagination, auth/404/offline errors and more than the bounded 30-version / 20-page limit produce `incomplete`. Stable assessments cover stable versions in the range; prerelease assessments include prereleases. This is a net source/test file delta between the exact endpoints plus complete release notes for the included versions.

Each raw HTTP response is retained as `response-<sha256>` in the explicit cache outside the checkout. The assessment output lists URLs, raw digests, byte counts, content types and cache-relative filenames, with a path-independent `captureIdentity`. It records the package source SHA and tag-to-npm-artifact link as unknown/unverified unless separately established. `ready-for-comparison` means these four upstream snapshots or deltas were actually fetched, parsed and checked; it is **not** a CSS/browser compatibility result or baseline admission.

## Machine contracts

All objects have `schemaVersion: 1`. Unknown versions fail consumers. Paths here are canonical for #3828/#3829/#3838; per-fixture imported provenance belongs with their later fixture manifests, not in the accepted record.

| Record | Required fields and meaning |
| --- | --- |
| `reference/bootstrap.json` | Exact `package`, `version`, `channel`, `registry`, `tarball`, `integrity`, `sha1`, `verifiedAcquisition`, and `source` (`repository`, observed tag, nullable package Git SHA, status). It is a candidate only. |
| `reference/accepted.json` | `acceptedReference: null` initially. A later admitted object must carry exact package/version/channel/SRI/artifact digest, lock and toolchain identity, source status/SHA or explicit null, profile ID/version/revision/digest, and admitting evidence report ID/digest. |
| `reference/reviewed-through.json` | `reviewedThrough: null` initially. A later object carries assessed package/version/channel/SRI, disposition, plan ID and assessment/report identities. Rejection can advance this record without advancing accepted. |
| Plan output | `kind: wind-reference-plan`, exact `candidate`, `previousAccepted`, `previousReviewedThrough`, `changes`, `inputs` (SHA-256 of profile, bootstrap, both live records, lockfile, all command implementations and Node runtime identity), `toolchain`, `profile`, `admission: unassessed`, and content-derived `planId`. Candidate changes, input edits, tool changes, runtime changes and stale replay invalidate the ID. Rehashed schema/transition lies still fail semantic replay. |
| Assessment input | `--plan` points to the immutable plan; `--cache` is an explicit path outside the checkout. No caller-supplied delta bundle can produce upstream readiness. The tool fetches exact npm/GitHub/codeload URLs derived from the plan. |
| Assessment output | `kind: wind-reference-assessment`, `schemaVersion: 1`, plan/candidate identity, `status: incomplete | ready-for-comparison`, `findings`, `captureIdentity`, raw `captures`, four `sections` when complete, source status and nullable package Git SHA, and both advancement flags `false`. The sections carry exact release versions/body digests, artifact file changes, source file changes and test file changes. `tagToNpmArtifactLink: unverified` is explicit. |

For a catalog JSON input, use `{ "complete": true, "pages": [{ "index": 1, "totalPages": 1, "truncated": false, "next": null, "items": [<exact npm package metadata objects>] }] }`. Preserve the original registry response/source identity beside any catalog snapshot. The live assessor does not trust catalog assertions as upstream evidence; it fetches the current exact metadata again. If a source lacks an authoritative complete tree or continuation marker, assessment is incomplete.

## Downstream interfaces

The future `compare` command (#3829/#3831) consumes a validated plan, the exact acquired reference identity, profile and fixture manifest digests, Wind source/catalog/config/lock identities, and per-case/per-engine raw outputs. It will emit a report with every required case and control counted exactly once, actual and expected reviewed-difference occurrences, failures and browser inputs. A source-inspected or `ready-for-comparison` record cannot substitute for that report. #3828 owns inventory and fixture expansion; #3829 owns the execution harness.

The future checked `promote` command (#3838) consumes the immutable plan, complete assessment, independently reviewed comparison report, profile revision and current live records. It must reject stale inputs, incomplete mandatory engines/cases, unexplained differences and missing source-provenance decisions. Its output is a proposed accepted transition and a separate reviewed-through transition with exact evidence IDs. Promotion is **not implemented here**; no command silently edits these records. Until that checked transition exists, both remain null and no compiler or browser parity is claimed.

`plan` is a zero-write dry run. `assess`, `acquire` and `probe` write only to the explicit cache outside the checkout, with symlink-resolved path checks. None installs into the project, advances pins, edits tracked/untracked files, or posts externally. The cache can be deleted at any time. Focused tests assert before/after checkout status and identity; network, path, integrity, pagination and replay failures use deterministic offline responses.
