# Plugin probe publication barrier

Continuation of draft #4120 after `756932860fbefe07f94a513536c4d2bd25cd03c6`.
This is a prerequisite for lifecycle work, not completion of the production
plugin migration or active-build cancellation gate.

## Change

The standalone native example previously called `Bundler::write()` before it
checked warnings or completed `close()`. Rejected output could already exist,
and early errors could bypass its explicit close call.

It now owns a one-shot bundler, generates in memory and rejects unresolved-import
warnings and any shape other than a single JavaScript chunk. Close failures
reject otherwise valid generated bytes. A private close observer distinguishes
Rolldown's automatic scan-error close from paths that need explicit close. The
helper clears retained driver state after the close attempt, including close
failure, and drops the bundler rather than exposing it for reuse. The example
tears down its private Tokio runtime before publishing output bytes.

Publication uses an exclusively created new file. Pre-existing files, directories
and symlinks are not overwritten, followed or removed. A returned write error
closes its handle before removing the incomplete output it created; removal
failures are reported. The CLI requires a new absolute output path. This is not
a change to production's existing staged-file API or a replacement for its locks.

The package externalization hook, compiler options, dependency pins, Cargo.lock,
production caller, shared adapter, configuration loader and Node host are
unchanged. The existing 18-contract esbuild/native matrix is retained verbatim.

## Pinned close ownership

At Rolldown `24bc2d0b5c9a8c87ac8d1ce8cb9a2df61b8624b9`,
[scan failure](https://github.com/rolldown/rolldown/blob/24bc2d0b5c9a8c87ac8d1ce8cb9a2df61b8624b9/crates/rolldown/src/bundle/bundle.rs)
calls the plugin driver's close hooks directly. It does not mark the separate
[BundleHandle close flag](https://github.com/rolldown/rolldown/blob/24bc2d0b5c9a8c87ac8d1ce8cb9a2df61b8624b9/crates/rolldown/src/bundle/bundle_handle.rs).
An unconditional follow-up `Bundler::close()` therefore repeats resource hooks.
The driver also stops at the first failing close hook; its error can replace the
original scan diagnostics before `generate()` returns.

The probe installs its private close observer before its other probe plugins.
It records the original scan diagnostics and observes whether close started.
It does not retry a failed resource hook. Explicit close is still required after
successful generation, render failure or output rejection. Original generation
and close diagnostics are retained together. This is a pin-specific workaround
for the probe's installed plugins, not a general failure-tolerant multi-plugin
shutdown scheduler. Revisit it when the Rolldown pin changes.

## Checks and observed failures

`cargo test --locked -p zfb-rolldown-prototype --features native --example plugin_prebundle`
exercises real native generation, close-hook observation and native asset
emission. Coverage includes success, render errors, unresolved warnings, missing
relative imports, rejected additional assets, close failures, simultaneous
scan/render and close failures, partial writes, file/directory collisions and
Unix symlinks. Native error paths require exactly one close-hook invocation.
The success oracle requires an inline source map and no output before explicit
publication. Tests do not exercise active-build cancellation.

[Run 38676617496](https://github.com/Takazudo/zudo-front-builder/actions/runs/38676617496)
failed compilation on a missing async hook lifetime and failed formatting; no
regression tests executed. These errors were corrected in `5d24367e`.
[Run 38677049699](https://github.com/Takazudo/zudo-front-builder/actions/runs/38677049699)
then compiled and ran 12 tests: 10 passed and two failed. The missing-relative
oracle observed two close calls rather than one. The CSS fixture errored before
reaching the intended output-shape rejection; the corrected fixture emits an
additional asset through the real native `emit_file_async` hook instead. Neither
failed run is called green. The exactly-once assertion is retained, and new
native dual-error tests verify both primary diagnostics and no close retry.

`.github/workflows/rolldown-plugin-publication.yml` checks the exact pushed SHA
with Rust 1.99.0 explicitly selected, locked native and feature-off builds,
library and regression tests, and the unchanged 36-row differential matrix.
It records identities and retains failure logs. Its permissions are read-only;
it does not rewrite sources, modify branch refs, publish packages or deploy.
A configured workflow or unexecuted test is not a passing result. Final run
identity and results belong in the PR report, without relabeling an older SHA.

## Still open

Runtime teardown and close are **not bounded**. Dropping a future or adding a
Tokio timeout does not prove that native background work has stopped. Active
native cancellation, bounded quiescence, production stage ownership/stale-sweep
protocols and actual CLI-to-plugin-host acceptance remain unimplemented here.
Crash recovery and concurrent hostile pathname replacement during publication
are not established by this helper. It installs the no-native-file-write barrier
and normal-return error cleanup prerequisites only.

The real plugin caller stays on esbuild. PR #4120 remains open/draft. Overall
CI/provenance admission, Darwin/Intel/platform obligations and adoption remain
separate gates. No claim from an earlier source SHA is relabeled as current.
