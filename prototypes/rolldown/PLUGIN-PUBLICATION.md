# Plugin probe publication barrier

Continuation of draft #4120 after `756932860fbefe07f94a513536c4d2bd25cd03c6`.
This is a prerequisite for lifecycle work, not completion of the production
plugin migration or active-build cancellation gate.

## Change

The standalone native example previously called `Bundler::write()` before it
checked warnings or completed `close()`. Its early `?` / rejected-warning paths
could bypass the explicit close call, and failed acceptance could leave output.

It now generates in memory, rejects unresolved-import warnings and any shape
other than a single JavaScript chunk, and attempts close after every returned
generation result. A close failure rejects otherwise valid generated bytes.
When generation and close both fail, both diagnostics are retained with the
original generation diagnostic first. The example tears down its private Tokio
runtime before it publishes any output bytes.

Publication uses an exclusively created new file. Existing files, directories
and symlinks are not overwritten, followed or removed. A failed write closes
its handle before removing its own incomplete output; removal failures are
reported rather than hidden. The CLI now requires a new absolute output path.
This is not a change to production's existing staged-file API.

The package externalization hook, compiler options, dependency pins, Cargo.lock,
production caller, shared adapter, configuration loader and Node host are
unchanged. The existing 18-contract esbuild/native matrix is retained verbatim.

## Checks

`cargo test --locked -p zfb-rolldown-prototype --features native --example plugin_prebundle`
includes real native generation and close-hook observation for success, render
failure, unresolved imports, missing relative imports and close failure. It
also checks combined diagnostics, refusal to overwrite another owner's file,
and refusal to follow a symlink on Unix. The success oracle requires an inline
source map and verifies that output does not exist until explicit publication.

`.github/workflows/rolldown-plugin-publication.yml` checks the exact pushed SHA,
locked native and feature-off builds, library tests, these regression tests,
and the unchanged 36-row differential execution matrix. It records identities
and retains failure logs. Its permissions are read-only; it does not rewrite
source files, bypass a gate, publish packages, deploy or modify branch refs.
A configured workflow or unexecuted test is not a passing verification result.

## Still open

Runtime teardown and close are **not bounded**. Dropping a future or adding a
Tokio timeout is not proof that native background work has stopped. There is
still no accepted active native cancellation, bounded quiescence, production
stage ownership/stale-sweep protocol, or actual CLI-to-plugin-host acceptance.
Process-kill/crash recovery during publication is not established by this
helper. This probe only installs the no-native-file-write publication barrier
and normal-return error cleanup prerequisites.

The real plugin caller stays on esbuild. PR #4120 remains open/draft. Overall
CI/provenance admission, Darwin/Intel/platform obligations and adoption remain
separate gates. No claim from an earlier source SHA is relabeled as current.
